# 免费方案真实端到端验收（2026-11-05）

本轮在 `test/sponsored-real-e2e`（基于 PR #336 的 `1af032f1`）验证真实请求，补充此前使用模拟 IPC 的界面回归。结论：基础业务与凭据轮换流程能够跑通，但不能称为全部稳定或内容完全可靠。发现并修复了一项真实 CLI 配置错误；保留首次失败及后续复测，不以重试覆盖原始结果。

## 环境与证据边界

- 本机 Intel macOS，Python 运行正式应用代码；真实 Chromium 加载本分支构建的 MV3 扩展，并访问 PC Web、移动 Web（390×844）和初始化页。
- 正常请求使用已下载并验签的私有 Rust SDK `sponsored-runtime-2026-11-05.1`。Mac x86 归档 manifest SHA-256：`9c4f6dad43996b9882d54da4eb82412335b4eaf55c5bab5a4fca4a27478ec3de`。调用真实硅基流动 Qwen3-8B / Qwen3.5-4B、云端 BAAI/bge-m3；本地向量调用实际运行的 Ollama bge-m3。
- 四组业务矩阵使用隔离目录中的合成浏览历史、候选和反馈，业务组件、模型请求、数据库及向量缓存均为真实实现。B站公开搜索、GitHub 公开 Star 导入及后续公开候选抓取另行实测。
- 四组基线关闭自有渠道回退及另一免费模型回退，避免把替代模型的成功算给被测模型。单独复测开启免费互备时记录实际模型。没有调用自有付费模型，没有撤销或修改正式 Key。
- 多组实测部分并行，后续还运行了全量测试；延迟含后台竞争，不能用作两个模型或两种 embedding 的独立性能排行榜。结束时业务表记录244次调用、762,425输入token、164,755输出token，provider均为sponsored。业务用量表只统计已记录的业务调用，不包括所有探测、向量请求和未记录的失败，不能解释为零失败账单。

## 失败复测与内容边界

1. **8B 超时属于可用性失败，本轮未证明是能力失败。** 首次评估183.321秒后报 `SponsoredUnavailableError`，不是格式校验拒绝；后两项是依赖失败，不是另外两次模型故障。相同30候选在已完成后续学习的样本状态上复测，开启默认免费互备，完整评估、25条准入、12条文案、3条交付共163.569秒；调用记录全部仍为8B，未实际触发4B回退。不能据此声称已经验证了真实故障下的自动互备。
2. **4B 指令遵循有偶发性。** 首次没有执行全 `get_profile` + `read_memory`；同一云端样本完成后续学习后，重复同一任务指令，连续三次都执行两个工具并回答，耗时49.316 / 6.695 / 12.468秒。本地组合中的相同要求也通过。真实传输和工具执行可用，但不能保证每次都遵守完整步骤。
3. **追加内容约束检查两模型各5/5。** 包括被动浏览画像不写职业/经历和特质断言、六条候选的明确截止时间/时区及跨条日期边界、觉察引用只来自本批事件、三次流式响应和向量、明确自述经画像重建后保留。断言针对这些具体边界，不是全面事实核查。实际工具回答仍出现把园艺兴趣解释为“调节认知压力”等未经原始事件支持的动机；公开推荐也出现与技术兴趣关联较弱的娱乐内容，应保留质量风险。

业务评估日志仍有非法时效字段被降级为 `unknown`；这说明容错路径生效，不代表模型原始输出的每个时效字段都正确。

上述正式脚本共94项记录：90通过、4失败，其中包含补测，不是独立随机抽样的准确率。所有原始失败仍列于[脱敏汇总](assets/sponsored-real-e2e/summary.json)；脚本观测到的后台失败为0不包含随后故意注入的凭据拒绝实验。

## 本轮修复

真实 `openbiliclaw recommend` 在 `sponsored.enabled=true`、`fallback_to_user_provider=false` 的 legacy 配置下仍报 `llm.deepseek.api_key` 缺失，尚未进入模型请求。磁盘重载确认免费配置存在，原因是旧校验仍要求未参与路由的自有渠道凭据。

`validate_runtime_config()` 保留免费组件、embedding与其他运行时校验，仅在自有聊天渠道实际启用时要求其凭据/端点；明确开启自有回退后仍校验。增加保存→重载→CLI运行时校验回归，覆盖两种路由格式、两种向量模式、显式自有回退及非模型配置错误。最小复现先红后绿（3 failed/13 passed → 384项配置相关测试全过），再执行原真实 CLI 成功。

全量回归发现的四项失败已分别定位并修正测试：

- 断网恢复测试期待库存30，而测试服务在重读时已返回27。当前分支和原始 `1af032f1` 均复现，页面与测试文件均和基线字节一致。现在确认状态重读发生并断言最新库存27，保留卡片恢复与初始化门禁断言。

- Jev真实应用进程回归中的保存、热重载及三条候选评估都成功，但刷新后立即读下拉框，可能在配置异步加载前读到默认 `llm`。当前分支复现、基线同次对照通过；现在用可重试断言等待已保存的 `jev`，并保留Token空值校验。此回归使用本地合成Jev服务，不属于真实模型质量测试。
- 平台标签重试用例在当前分支和基线均失败。浏览器网络日志确认两次503后第三次配置已200，但测试服务器漏发 `/shared/` 下的设置脚本，触发 `mount` 异常，标签未刷新。测试服务器现在提供实际共享资源，并增加页面无异常断言；原标签/零库存/重试检查未放宽。
- POSIX显式端口单测假设18424永远空闲；本机另一个应用占用该端口时，产品正确选择18425却被判失败。该分支单测现在固定“端口可用”的探测前提，已有真实socket绑定/占用测试仍保留；没有停止用户进程。

测试脚本新增 `--embedding-mode local`，调用与产品相同的本地选择函数。未改模型参数、评分门槛、提示或失败判定来使验收通过。

## 尚未覆盖或尚未解决

- 本机项目、旧桌面数据位置与安装器默认目录保存的B站登录均实际返回 `-101`；已请求重新登录，但本轮未取得有效登录，因此**未验证本人账号历史/收藏/关注导入**。匿名B站搜索与公开内容推荐已验证。其他需要登录的平台也不能由本轮替代认证。
- 移动端为真实浏览器中的移动 Web，不是实体手机；本轮没有重新构建/测试签名 `.app`、Windows安装包或Linux/Docker真实推理。此前平台安装CI见[原记录](2026-11-05-sponsored-renewal.md)，不能把它当作本轮实体平台全功能验收。
- 本轮未进行多用户压力测试。没有故意耗尽生产额度或制造服务商429；它们的状态分类仍依赖现有离线回归。8B偶发长等待、4B偶发漏工具、解释过度推断、少量真实推荐相关性偏弱仍然存在。
- 图片理解、图片向量、可选Jev和其他增量能力不在已确认的基础功能范围内。
- 分支通过测试不等于已经合入或发布主程序；本轮不修改正在使用的用户安装与配置。

## 复验入口

使用新的隔离目录，正常调用无需把共享Key放入命令或配置。先确保本地模式已有Ollama/bge-m3：

```bash
PYTHONPATH=src python scripts/sponsored_system_acceptance.py \
  --root /tmp/obc-free-live-8b-local --model Qwen/Qwen3-8B --embedding-mode local
PYTHONPATH=src python scripts/sponsored_http_acceptance.py \
  --root /tmp/obc-free-live-8b-local --port 50303
PYTHONPATH=src python scripts/sponsored_quality_acceptance.py \
  --root /tmp/obc-free-live-quality
```

更换模型和embedding组合重复；30候选使用 `--candidate-count 30`。`acceptance.json` 保留每例状态、耗时、模型和调用记录，任一失败返回非零。新目录有防覆盖检查；实际浏览器与鉴权实验使用本轮隔离输出中的控制脚本和人工可见操作，未替换请求返回值。

回归结果：完整 `pytest` 首轮为 **12,544 passed、70 skipped、4 failed**（3,583.35秒），失败为上述四项。修正后按失败范围复测：库存恢复、Jev与完整transport文件 **22 passed**；平台浏览器文件 **3 passed**。配置相关 **384 passed**，Ruff与MyPy（386文件）通过，扩展构建成功。修正测试后没有再重复一小时全套，不能把首次完整扫描改写成零失败；最新提交的CI以PR实际状态为准。
