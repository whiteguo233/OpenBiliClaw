# 聊一聊真实多轮端到端验收（2026-10-14）

## 结论与标准

用户澄清标准：**允许一定追问，不能无限追问**。本轮不再把任何可选尾问都判为失败，
而检查是否给出有用结果、信息足够后是否收敛、用户让系统决定或结束时是否停止追问。

基于 `94bf6962`，本轮 **20 次真实回复未复现持续追问而不交付结果的循环**：
18 个 API durable 回合全部 completed，另有 CLI 两轮成功并正常退出。
这支持按当前标准通过本轮抽样验收，不代表所有模型、所有历史和自定义角色的数学保证。
未合并、未发布，本次没有继续调整产品提示词或代码。

## 环境与真实性

- 使用独立 worktree 的生产 `create_app()`、真实 Uvicorn HTTP/SSE 服务
  `127.0.0.1:18447`，同机配置的真实模型路由。
- 桌面 Web 和移动 Web 经真实浏览器操作；其余探索场景通过 HTTP 创建会话、创建
  durable turn、消费 `/api/chat/agent/stream`，再从 SQLite 核对结果。
- 没有替换模型、工具或学习函数。`get_profile`、`read_memory`、`write_memory`
  真实执行，使用隔离数据库/记忆；自动发现、账号增量同步、自动更新关闭。
- 初始空数据，通过测试对话形成一个虚构用户的共享画像；5 个会话共享该画像，
  不是统计独立的 5 次实验。未复制真实聊天、观看历史或画像，未修改用户生产数据。
- 主模型出现限流并触发真实降级。用量表记录：`agent.chat` 共 25 次模型调用，
  `deepseek-v4-flash` 3 次、`sensenova-6.8-flash-lite` 22 次；CLI
  `soul.dialogue` 两种模型各 1 次。25 是工具循环中的模型调用数，不是聊天回合数。
  因此结论针对这次实际主备路由，不能说只验收了 DeepSeek 单模型。

## 场景结果

| 场景 | 真实回合数 | 观察与判定 |
| --- | ---: | --- |
| 桌面明确需求，随后移动页新需求 | 4 | “最近只想看轻松的”直接接受；致谢回复“不客气”；移动页给出三个睡前内容类型；“今天先这样”回复“好，晚安”。通过 |
| 主动探索，持续补充信息 | 5 | 首轮问方向；回答慢节奏、看人做事后给建议；“怕无聊”得到解决建议；补充成品变化后记录；“不用再分析”直接结束。通过 |
| 不知道、让系统决定、仍选不出 | 3 | 首轮给选择；“你决定吧”后直接给默认方向；“选不出来”后建议先试一条，没有继续要求选项。通过 |
| 模糊但可做的内容类型建议 | 2 | 先给类型并可选询问是否要具体内容；明确说类型够了、先这样后结束。按新标准通过 |
| 连续含糊回答，跨进程重启 | 4 | 前两轮提出探索问题；重启后第三轮形成总结/建议，附一个可选追问；继续回答“修复吧”后第四轮给出结论并结束。通过 |
| CLI 旧聊天路径 | 2 | 给出两个放松内容类型；“就这样，谢谢”后自然结束，`exit` 正常退出，退出码 0。通过 |

最容易误判的是跨重启场景：前两轮主要在澄清，第三轮已经交付可用结论，尾部仍有
一个可选问题，第四轮收敛。按“零尾问”会判失败，按用户现在的“有限追问、有结果、
能够停下”标准，本次通过。并未声称后端有两轮硬计数器。

## 链路核对

- 18 个 durable turn 全部 completed，0 pending、0 failed。
- HTTP 脚本覆盖的 14 个回合逐一核对 SSE `done.reply` 与 SQLite `reply`，全部一致。
- 脚本场景捕获真实工具调用：`get_profile` 3 次、`read_memory` 3 次、`write_memory` 3 次。
- 在连续问两轮后停止旧进程，以同一隔离数据启动新进程；后续 turn 仍绑定原会话。
  浏览器刷新后可见完整前后历史，回复根据已聊内容继续并收敛。
- CLI 使用实际 `openbiliclaw chat`，输入两轮消息后 `exit`，不是直接调用 prompt builder。
