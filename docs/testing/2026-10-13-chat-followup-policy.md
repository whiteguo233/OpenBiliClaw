# 聊一聊收敛规则与验证（2026-10-13）

> 后续：2026-10-14 用户明确接受有限追问。本页保留当日严格标准与失败样本；按新标准的
> 20 轮真实端到端验证见[后续验收](2026-10-14-chat-followup-e2e.md)。

## 产品决策

优先满足当下需求，允许画像暂时不完整。对话每轮选择「交付结果」或「必要提问」，
不把交付结果变成下一轮访谈的开头。状态名称仅用于内部规则，不展示给用户。

| 情况 | 预期行为 | 结束条件 |
| --- | --- | --- |
| 需求明确 | 直接回答或执行必要步骤 | 需求得到回应即可结束 |
| 模糊但可做 | 给一版可纠正结果，必要时说明假设 | 有用结果已交付，不补问偏好 |
| 不同理解明显改变结果或执行范围 | 先用上下文/工具补齐，仍不足才问一个关键问题 | 普通需求默认一轮澄清后给结果；缺必填参数则说明限制并停下 |
| 用户主动探索 | 每轮一个具体问题 | 信息够用或连续问两轮后总结，以陈述结束 |
| 用户让系统决定、表示不知道或想停 | 采用合理默认或结束 | 不追问这些表达的原因 |

用户主动继续或提出新任务时重新判断。角色选择本身不等于同意持续访谈。
暂时偏好保留时间范围；没有证据的动机保持未知；缺少授权/必填参数时不猜测执行。

## 实现范围

共享 `build_socratic_dialogue_prompt()` 同时覆盖新 agent 入口、旧普通/流式回复与
旧工具路径。默认伙伴和口味探寻师去掉主动深挖的冲突指令，agent 最后的工作纪律
重申结果与追问互斥。没有新增分类调用、会话计数器、输出截断或关键词路由。

这是提示词行为约束，不是后端强制状态机；一轮/两轮来自本次产品取舍，不是模型
统计校准。用户自定义角色仍可能存在冲突，模型切换后也需要重新验收。

共享后端覆盖插件、桌面 Web、移动 Web 和 CLI 的提示词入口；没有修改前端、协议、
工具权限或画像学习算法，本次未进行四端浏览器/CLI 真实界面验收。

## 真实模型抽样及剩余问题

使用本机配置的 `deepseek-v4-flash`，仅发送虚构聊天；内存隔离，画像/推荐/写入工具
使用测试替身，未修改用户实际画像、推荐或配置。最终复测经过 `SocraticDialogue`、
`AgentLoop`、`LLMService`，不是浏览器端到端测试。早期直接请求模板的实验未正确提供
工具协议，出现正文工具调用，不能当作完整聊天验收。

最终一轮四个场景的人工判断：

| 场景 | 观察 | 判定 |
| --- | --- | --- |
| 明确说最近只想看轻松、不烧脑 | 简短接受后结束 | 本次通过 |
| 问过一次，用户说不知道、让系统决定 | 给出具体方向，未再提出偏好问题 | 本次通过；仍有「不对味随时说」式可选收尾 |
| 主动探索已经连续问两轮 | 总结已知口味、给出内容方向后结束 | 本次通过 |
| 只要几个轻松内容类型 | 列出类型后仍让用户说明偏向看人做事还是风景动物 | 未通过严格收敛要求 |

前序样本中，口味探寻师面对明确需求、旧入口面对明确需求、用户说「先这样」均出现
正常结束；默认伙伴的附加问题/邀请在多次运行间波动。含糊「别推荐这种了」的样本还
出现未经澄清便推断屏蔽范围的问题；本次没有增加写入前的程序性范围校验，不能把它
视为已解决。

结论：统一规则与移除冲突指令已完成，但严格的「零多余追问」尚未通过模型行为验收。
此分支保留作为可审阅改动，不据此声称问题已彻底解决或直接发布。若后续要求硬保证，
需另行设计可验证的回复决策/执行范围契约，权衡额外模型延迟、流式呈现和持久会话状态，
而不是继续堆叠提示词或裁掉含问号的句子。
