五个简单请求中位数 **2.874 秒**。这些是端到端样本，模型路由与上游耗时会波动，
不把上一轮 1.644 秒中位数当作固定性能保证。画像请求确实执行 `get_profile`。

三轮接口读测中，健康接口首次 1.290 秒、运行状态首次 1.802 秒；热请求约 2–3 毫秒。
待聊确认列表约 20–32 毫秒，未再出现此前单次约 4.66 秒的轮询阻塞。

## 断流、重试与任务生命周期

  持久化事件始终为一次 tool_call、一次 tool_result、一次 final，历史仅一条。
- 后台只读配置查询任务 3.518 秒完成，只生成一条结果摘要。
- 另一个后台任务实际完成三次工具调用后取消，1 秒后状态仍为 cancelled、
  步骤不增长、无报告或摘要；重复取消返回 409。

## 本轮发现

1. 旧长历史会话发“你好”时，真实回复仍出现 `[09-26 18:12] 在。`。
   上轮的提示词规则不能稳定阻止内部时间标签被模仿，需要修复上下文构造。
2. 320px 宽度下，移动页顶部“在线”状态被挤成上下两行。

修复将 Agent 最近 20 轮历史改为明确标注的 JSON 引用记录，原角色、原文、本地时间、
回复目标分字段提供；旧污染仍可被准确引用，但不再作为带时间前缀的 assistant 示例。
legacy 历史格式、数据库原文、学习与审批绑定不变。回归先在旧实现失败，再验证
真实 durable 历史恢复、25 轮到 20 轮窗口、时间问答、原样引用及回复目标保留。

移动端在 360px 及以下将状态区间距从 12px 收紧到 6px，避免连接文本和操作按钮
互相挤压；保留其余布局和点击区域。

新代码重启后，使用原先连续三次泄露标签的 **同一个 default 会话**复验：

| 真实请求 | 实际回复 | 耗时 |
|---|---|---:|
| 你好 | 在。 | 3.192s |
| 谢谢 | 不客气。 | 1.875s |
| 只回复：移动恢复正常 | 移动恢复正常 | 2.082s |
| 最近一次发“你好”是在几点几分？ | 最近一次是 **09-26 18:21**。 | 3.962s |

前三条均不再出现时间前缀，第四条准确匹配该问候的数据库时间
`10:21:32 UTC` → 本地 `18:21`，时间理解仍有效。
320px 新 CSS 实际加载后，“在线”区域由约 19.95×30px 恢复为 22×15px，
两枚操作按钮由约 39.9×44px 恢复为 44×44px，页面宽度保持 320px。

- 桌面浏览器查询推荐、核对稍后列表并执行 `save_item`，约 8 秒完成；
  数据库确认新增内容及列表归属。
- 查询观看历史后执行 `submit_feedback`，约 7 秒完成；真实推荐记录与反馈事件
  对应。发送后立即切换会话并输入草稿，原回合未混入新会话。
- 移动端立即出现用户气泡与等待状态。回复期间继续编辑时保留原输入节点、
  112px 多行高度、选区和焦点；向上阅读时完成回复不改变滚动位置。
- 390×844 和 320×568 无横向溢出，发送按钮 44×44；仅收缩 visualViewport
  到 400px 时聊天区仍有 178px、输入底部位于 378px，恢复后布局正常。
- 角色选择在刷新后保持，切回默认会话恢复其原角色。
- 发送后短暂离线并刷新，联网后原 turn 完成且只显示一次。此浏览器场景没有捕获到
  底层 TCP 断开点；工具结果后明确断开 HTTP 的保证来自前述独立生命周期测试。
- 真实系统管家查询配置并生成 `agent.loop_max_steps` 63 → 62 审批卡，手机页面
  实际点击批准后显示“已批准并执行”。后端 `executed_at - decided_at` 为
  **0.068530 秒**，磁盘读回为 62，重复批准返回 `already_executed=true`、
  `queued=false`；前后后台 LLM 活跃数均为 1，事件通道均未暂停。
- Console 仅记录主动离线和测试服务重启产生的预期连接错误；新服务的四条真实
  对话和批准流程无新增 JavaScript 或网络错误。

## 后台学习的未通过项

检查完整服务日志时发现，后台对话学习的画像重建有一次失败：主备服务出现限流，
继续回退的服务返回 HTTP 400 `inference request is invalid`；已有的精简历史重试
仍失败。修复前 `5779c613` 的本轮服务日志也出现相同错误，且发生在关闭服务之前，
不是这次时间标签修复新引入的问题。

代码核对显示，学习仍接收原始用户消息和最终回复，不消费新历史 JSON；该画像
重建入口使用 `history=[]`，本轮也没有修改画像构造、模型路由或 16384 输出预算。
精简历史重试在此入口无法缩小已为空的 history，不能把这次重试失败视为已排除
其他上下文容量问题。失败请求没有完整的上游参数诊断回执，故无法进一步归因。

因此本报告的“通过”仅覆盖上述实际验证的聊天、工具、审批和任务流程，**不宣称
后台画像学习全链路通过**。画像构建异常时既有代码保留原画像；这不等于所有学习
阶段都没有写入。具体上游拒绝原因无法仅凭该通用 400 信息确认，未通过猜测修改
provider 参数或隐藏错误。
