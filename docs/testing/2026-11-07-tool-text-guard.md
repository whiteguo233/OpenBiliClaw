# 免费模型工具协议正文修复验收（2026-11-07）

本次继续在 `feat/unified-sponsored-providers` 上修复[上一轮实测](2026-11-07-fixed-providers-live.md)发现的 Qwen3.5-4B 正文混入工具 JSON。代码基线为 `51eb1627`，改动位于 AgentLoop、对话入口、免费模型适配层及默认链保存后的即时应用；没有改动 Rust SDK、凭据、配额或配置字段。

## 修复与失败证据

1. 原回复先成功执行 `read_memory`，随后在正常回答末尾追加 `{"tool_call":{"name":"get_profile","arguments":{}}}`。记录回放最初失败，显示与最终回复都泄露了这段协议文本。现在普通正文即时流出，只暂存可能的末尾协议段，完整且属于已注册工具的封套会被移除。
2. 第一版检查在真实环境仍失败。原因是 `append_output_language()` 自动添加的 `Keep JSON keys...` 被误认为用户要求保留 JSON。中英语言回归在修复前为 2 失败 / 2 通过；现在 `SocraticDialogue` 单独传入用户原文，语言规则、记忆引用和历史消息不会影响当轮判断。
3. 第二轮真实 8B 对照发现：用户要求展示 JSON 示例时，模型走了 `get_profile → suggest_skill → get_profile`，没有保留示例。免费适配器对外实现项目工具接口，内部仍使用提示词模拟协议，并非向硅基流动直接发送原生 HTTP 工具字段。原协议没有明确的原样 JSON 答复通道；补充 `{"reply":"..."}` 后只解封一次，不再把其中内容解析为操作。同时工具解析只接受纯 `tool_call` / `tool_calls` 顶层对象，带答复或说明字段的对象保持数据。
4. 第三轮 4B 普通工具请求又出现完整的 Markdown 工具代码块，没有执行 `read_memory`。先复现裸协议通过、两种围栏失败，再将完整的末尾工具围栏纳入同一检查及一次纠正流程。未知/不完整代码、其他代码与明确索要的示例保持原样；提示词明确要求真正调用使用裸 JSON。
5. 第四轮 8B 连续成功读取 `read_memory` 11 次，没有产生正文，96.87 秒后遇到首段超时。增加只读无进展检测：连续两次的调用计划和完整结果相同后，第三个相同计划不再执行，转为无工具汇总。回归覆盖变化结果、变化参数、写操作和失败读取不会误触发；不会缓存或伪造工具成功。
6. 第五轮同场景两次通过（13.139 / 11.306 秒，两次读取后收敛），但示例对照未满足原断言；旧夹具没有在断言前保留正文，无法进一步归因。后续改为在用户请求中给出明确的 JSON 原文，并先保存全部结果、再判定，不隐藏失败。
7. 第六轮一条 8B 请求在无正文、无工具动作时 30.215 秒超时。真实异常链为 `SponsoredUnavailableError → LLMProviderError → LLMProviderExecutionError`，API 原本仅判断最外层类型，导致持久重试无法识别。复现中没有 `retrying: true`；修复后流式和后台入口沿异常原因识别，保留最多两次重试和已开始工作的禁重放边界。最终验收按前端实际流程先创建 durable turn，再消费 SSE / 轮询权威状态；前六轮直接流式诊断的失败仍单独保留。
8. 第七轮 4B 返回完整工具围栏后，又声称“已读取核心记忆”，实际没有工具事件。先加入失败回归，再扩展隔离范围：完整工具段之后的声明也不作为成功依据，整段隔离后请求一次纠正。纠正后的工具调用经过正常分发，随后才能形成答复；保留此前已显示的普通正文。
9. 第七轮 PC 从 8B 切换 4B，夹具等待 60 秒未生效；随后清理测试进程时，学习排空报 `CancelledError`。这不是生产 25 分钟排空上限到达的证据。根因是 PC/插件整表保存始终附带 Tailnet，后端仅凭字段存在便禁止默认链即时应用。补充未修改 Tailnet 回显后，两种运行模式的测试均先失败；现在只有真实变更或凭据操作阻断即时应用，完整配置比较继续防止无关变更被遗漏。
10. 第八轮两次配置切换通过，但 4B 三条自然工具请求中一条仍没有调用记录，却声称“已读取 core 记忆，当前兴趣信息充足”。服务日志显示本轮触发了协议纠正；对此补充同样响应的失败回放，确认原纠正流程会直接接受无证据的文字。现在纠正前无工具结果时，纠正回复必须走正式调用；否则暂存正文后抛错，不显示、不落成成功回复。已有工具结果的收尾可直接纠正，不重放已完成动作。这不能证明未经过纠正的任意回复也不存在幻觉。

正文检查不会执行文本中的工具调用。只有协议文本、没有正常答复时，AgentLoop 最多进行一次纠正；重复失败按原错误路径上抛，不形成成功的空回复。真实工具调用继续走注册表参数校验与审批。正常代码、引用、未知对象、不完整 JSON 及用户原样数据请求保留；此检查不承担通用内容真实性验证。

纠正前无工具结果时，纠正正文会暂存到正式调用校验结束；无调用则显式失败。对已执行工具的收尾仍允许直接回答，避免为纠正格式重放操作。

## 真实请求范围

使用 macOS Intel、正式验签 SDK `2026-11-06.2`、Core `0.3.234`、实际 Uvicorn HTTP/SSE 后端和 Chromium。两个全新临时目录分别从空 LLM 默认链、未选择 Embedding、旧赞助开关关闭开始，`runtime_path` 保持空值，由正常组件发现流程连接 Rust。模型与 BGE-M3 都实际请求硅基流动，没有模型替身或其他 Provider 兜底。

为稳定触发原问题，在临时数据目录放入仅允许 `get_profile` 的测试 skill，要求模型返回上一轮记录中的固定正文与 JSON。每个对照使用独立会话：普通请求应只留下正常回答；明确索要原样 JSON 的请求应保留示例，并且不得执行工具。断言同时检查 SSE 增量、最终回复与数据库 turn。该测试 skill 仅用于隔离验收，不随应用分发。

各轮测试覆盖初始化首位、PC 双向切换、后端重启持久化、手机网页实际流式聊天、扩展配置页的三个真实探测，以及 BGE-M3 的三路并发向量；个别失败轮次未完成所有项目，详见分阶段记录。扩展使用真实 popup HTML/JS，但 `chrome.storage/runtime` 由宿主夹具提供，不能据此声称重新验收商店安装或浏览器权限。所有输入均为合成数据，临时后端、目录和对应 Keychain 账本在结束后清理。

真实阶段结果、失败阶段和拦截日志计数保存在[实测数据](2026-11-07-tool-text-guard.json)。前一轮 8B 两跳工具流程耗时曾达到 40.863 秒；格式修复不改变模型的推理能力或承诺上游时延。

第八轮完成双模型的配置与向量验收；第九轮仅重测最后改变的 4B 对话检查。

接入与配置切换可以验收，两个免费小模型仍不能承诺完成所有日常任务。修复让已知协议错误、重复读取及部分不实完成声明能够纠正或明确失败；不能把失败标记替换成能力提升，也不能保证上游恢复。工具调用仍使用提示词模拟，8B 的示例意图误判属于未解决的语义限制。没有用付费模型替代失败样本，也没有修改用户正式配置。

本次均为合成小样本，不作为能力排行榜或可用率统计。第八、九轮清理浏览器时的 Playwright `Target closed` 来自夹具响应观察器，后端及临时账本均已清理，不计为模型请求成功或失败。
