## 本轮发现并修复的代码问题

首次自动安装完成后，如果没有打开过采集会话，旧实现没有挂空闲回收和解释器退出清理。
真实空来源实例在准备完成 **159.6 秒**后仍运行；API 自动准备与显式准备的最小回归均失败。

`6a191c35` 将原来仅工作流持有的回收逻辑集中到 `EgoSetupManager`：

- `prepare()` 成功后统一挂默认 120 秒空闲回收和退出清理，覆盖源码准备 CLI 与 API。
- 服务启动或显式准备复用已在线宿主时也补挂回收；就绪但离线的启动检查继续保持只读。
- 工作流关闭委托给同一管理器。停止前仍检查跨进程会话租约，采集／接管会话不被误停。
- 新增准备入口、已在线复用、活跃会话保护和退出清理回归；旧会话回收回归继续保留。

首次官方包下载、验签、自动设置和握手发生在基线运行阶段，约 12 分钟完成，无人工配置
或服务重启。修复后复用该安装，实际验证 CLI 准备、API 准备及管理器完成后的回收，没有
把它表述成最终代码重新下载了一次安装包。

## 失败定位与复验边界

哔哩轻小说失败时，对已发布版本的只读诊断记录：入口与 document 请求全部获准，
`blocked_requests=0`，没有被来源／公共 DNS 权限策略拒绝。仅在私有诊断脚本的固定宿主
副本中追加安全的网络错误枚举，实际得到 **`net::ERR_CONNECTION_CLOSED`**；没有改动
产品宿主、允许范围、证书策略或采集计划。最后再次启用原来源，由正常调度运行版本 2，
仍在 4.8 秒后返回导航失败，并未自动恢复。

HTTP 仅作为独立网络诊断：匿名直连 www 返回 403，裸域返回 301；这些结果没有计作
Ego 采集成功。机器启用了系统 HTTP/HTTPS/SOCKS 代理；连接关闭的站点／网络／代理
责任边界未进一步归因，不能据此声称站点整体离线或要求用户登录。

模型早期曾返回 429 与 `workspace routing discovery failed`，末轮首个聊天尝试明确失败。
额度检查仍有余量，没有消费 reset。当前桌面 CLI 与插件 CLI 的版本字符串同为
`0.162.0-alpha.17.2`，二进制不同。后半程改用当前桌面客户端二进制，模型、协议与指令
保持；小请求和原失败请求独立完成，随后原生聊天完整通过。尚未证明此前故障仅由某一
二进制导致，也没有把录制回复注入产品。

另一套新假设 fixture 的正确回复省略了“通勤”，原固定词断言误判失败。测试新增非空的
场景关键词参数，默认仍为“通勤”；回复目标、待确认移除与持久状态断言保留。
中断的测试卡片通过正式拒绝 API 收尾，最终完整复验使用新的两条互异 fixture。
