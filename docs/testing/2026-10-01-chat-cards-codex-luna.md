## 修复与回归

桌面聊天提示条原先设为 `pointer-events:auto`，悬停还会暂停消失。在“聊聊”后点击卡片“稍后”，Playwright 明确报 `toast-item intercepts pointer events`，没有发出动作请求。把提示条移到输入区上方仍会遮住卡片。

聊天页提示条现在不接收指针事件，自动按时消失；其他页面保留原交互。原卡片操作在应用该 CSS 后成功。新增 `scripts/browser/chat-toast-hit-test.js` 使用真实页面样式，在输入区上覆盖提示条：恢复旧 pointer-events 时点击超时，新样式点击成功。脚本在已打开聊天页的 playwright-cli 会话中通过 run-code 执行。

## 限制与后续优化

- CLI 启动、登录传输和测试转接增加开销，普通问答 7.9–59.5 秒、工具回合约 83 秒的样本不能作为生产 API 的延迟基准；简单问题回答长度已符合要求，但不能因此声称性能已优化。
- 有另一张活动卡片时，直接确认不同卡片会返回 stale_anchor，并提示先结束当前条目。防串话有效，但可增加“跳到当前讨论”入口，减少用户寻找卡片的成本。
- 已在其他窗口结算的上下文会显示“失效，请重新打开”，建议区分“已完成”与真正失效，避免让用户以为结算失败。
- 疑惑 observation 自带句号时，模板会显示重复句号，属于文案打磨项。
- 本轮未覆盖所有外网工具、真实平台登录、真实手机键盘、iOS、断网恢复的全部组合；不得把本报告解释为所有功能全部通过。
