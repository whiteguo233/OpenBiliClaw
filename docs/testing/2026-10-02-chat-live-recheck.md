## 发现与修复

1. **插件没显示逐字内容**：SSE `delta` 未进入临时正文。按回合/hop 累积并即时渲染；`thinking` 清除中间正文，`final`/`done` 权威替换。历史刷新及切回会话保留临时正文，终态仍要求 `done`。
2. **插件打开卡片后点不到按钮**：展开待聊列表将消息区压成 0px，按钮被列表/输入框截获。成功打开后自动收起列表、定位卡片；失败仍保留列表重试。430×750 实测消息区恢复 127px，新卡无需刷新即可操作。
3. **legacy 流式漏读链接**：`respond_stream()` 没有调用已有链接摄取逻辑。与其他两条回复入口对齐，保留历史/学习原文、当前卡片绑定，无链接快速跳过、摄取失败降级。
4. **legacy 与后台恢复竞争时重复摄取/学习**：执行锁内未重查完成状态，完成写入又在锁外。同一回合真实产生了两条分享和两条 dialogue 事件。现锁内重查并提交；已完成/失败只重放，身份冲突提前拒绝。
5. **插件发送入口先触发后台补算**：创建后先 GET pending turn 再连 SSE；GET 本身会唤醒后台 worker，可能导致前端只拿到最终重放。已改为首轮直接使用创建/历史已有 turn 建立 SSE，只有断流后才 GET 恢复；真实插件收到 13 个 delta，完成前正文可见。

以上均通过实际失败或执行真实调用路径的失败回归定位。整合时保留已有事件增量持久化，同时确保 token delta 不写入 `agent_events`。

## 测试方式与边界

`GET /api/chat/turns/{id}` 会触发 pending 回合恢复，不能拿它做无副作用的实时观察。最初脚本立即轮询，确实使后台先完成并只重放 final/done。后续改为先等页面 SSE 完成，再 GET/SQLite 核对；插件自身也存在这一竞争，单独修复。没有用分割完整回复的方式伪造模型 delta。

单进程全量 pytest 最初读到了当前测试配置/数据，发现后停止（3125 passed、2 skipped，无失败）。随后将完整 9914 个用例、424 个文件分为四组，分别在默认无密钥配置、独立 data/cache 的临时 root 中执行，避免与真实请求服务交叉。结果另列。

仍需关注：真实上游 HTTP429 与长尾等待；旧路径偶尔没有严格遵守“只说标题”的短答要求；疑惑 observation 自带句号时模板会重复句号。疑惑结算成功不等于已经验证了推荐过滤效果，不能仅凭模型一句“以后不给你推”判定推荐策略生效。

本轮并发保证覆盖已完成请求重试/worker 与 stream 竞争，不宣称任意中途取消都具备副作用 exactly-once 保证。未覆盖实体手机键盘、iOS Safari、全部平台登录与全部外网工具组合。
