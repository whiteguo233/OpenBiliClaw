## 三端交互与本次修复

修复前，在 A 输入文字但不发送，切到 B 后仍看到 A 的草稿。三端都使用了一个跨会话的
输入值/保留变量。现在切换前按 session_id 保存实时输入，再恢复目标会话的值。
这是页面内存状态，不会把未发送内容传给服务器，也不承诺跨刷新保存。

- 桌面、移动、popup：A 草稿→B 空输入→B 草稿→返回 A 恢复 A，全部通过。
- 清空或成功发送后再次切回，旧草稿不复活。自动化回归覆盖三端实际切换函数。
- 桌面真实请求进行中切到新会话并输入，旧回复完成后，新会话的草稿和历史未被覆盖。
- 插件真实发送后回复 `56`；刷新并重新打开“对话” tab，服务器历史仍在，已发送输入为空。
- 移动页面的轮询、跨端历史更新和审批执行保持当前草稿；320px document/body 宽度均为
  320，没有横向溢出。风格面板可滚动，焦点落入面板，Escape 可关闭。
- 桌面任务中心实际显示本轮已完成、失败、已取消三类结果，没有把失败渲染成成功。

## 耗时诊断与未解决问题

在第二次测试服务启动时使用进程内临时计时器，记录 provider slot 等待、HTTP 状态、
耗时和请求长度；没有记录请求正文、凭据或请求头，临时计时器不进入产品代码。

- 截至最终流程核对，采集到 28 次 slot 等待，按毫秒四舍五入均为 0.000 秒。
  同一阶段模型 HTTP 状态为 200×24、429×8、400×2。这是部分时段采样，不是全部测试调用总数。
- 捕获前台 `agent.chat` 请求先 429，随后回退模型 200 的真实路径；后台也有 429，
  并出现 94.721 / 121.858 秒的长请求。不能通过提高本地并发解决上游限流。
- 后台 `soul.dialogue_insight` 将全部 477 条洞察放入 active_list；画像重建把 1,382 条
  awareness 观察全部放入 recent_awareness。画像请求的 ASCII 转义后 JSON 长度约
  133.8 万字符，并实际收到 400。仅凭 400 不能断言具体是上下文窗口超限。
- 用当前副本和同一 prompt builder 离线重建估算：对话学习约 5.7 万 Unicode 字符，
  画像 prompt 即使不含 active_insights 仍约 53.7 万字符，其中 awareness JSON 约
  49.3 万字符。这是快照重建估算，不是原始请求精确 token 数。
- 第一次测试服务退出时学习队列仍有 8 项，30 秒 drain 超时。前台聊天成功并不代表
  其后台画像学习已完成或成功。

这些证据确认真实限流和无界历史输入问题；最初 25–39 秒回合未逐个打 HTTP 时间戳，
不能把每次慢请求全部归因于同一个原因。本轮没有修改限额、模型路由、学习语义或删掉历史。

## 功能与流程优化建议

| 优先级 | 改进 | 根据与验收方向 |
|---|---|---|
| P1 | 学习上下文按相关性选择并合并处理 | active_list 应优先当前锚、用户明确引用和近期相关洞察；画像输入用增量与可追溯摘要。保留完整存储、确认/拒绝语义和注入白名单，补旧洞察引用与负反馈不丢失的回归，再验证请求体积与学习质量 |
| P1 | 把真实等待原因显示在聊天里 | 工具完成后可能继续等几十秒；显示“内容已读取，等待生成回复”或“服务繁忙，正在重试”，区分本地排队、工具执行和模型退避，不显示虚假的百分比 |
| P1 | 失败任务可一键重试 | 本轮手动重新提交即可成功，但 UI 只有查看/取消路径；新增带来源 task_id 的重试动作，保留旧失败记录，并确保审批写操作不会因重试重复执行 |
| P1 | 前台提供“停止生成” | 当前断网会继续执行，这是恢复语义；应另设显式停止协议，区分停止后续步骤与已经完成的写入，不能把关闭 SSE 当作取消成功 |
| P2 | 简答与成功提示更准确 | 数量问题曾额外列出所有内部 key；私网拒绝附带多段替代建议；算术完成也显示“这句已经记下”。普通答案只给用户所需信息，只有记忆工具确实成功时才说“已记住” |
| P2 | 聊天笔记提供可见管理入口 | 自然语言可增删改，但浏览/定位/核对仍靠模型；可增加小型笔记列表和修改预览，继续复用原值冲突检查与删除审批 |

以上是后续优化方案，本次实现仅包含草稿隔离。尤其学习上下文的有界化不能简单取前 N 条，
否则可能漏掉用户正在更正的旧洞察或绕过注入/结算约束。
