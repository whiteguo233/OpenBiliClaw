# NGA 经 Ego Lite 聊天建源真实验收

范围：已有通用网页 Discovery 的 capability-increment，复用
`docs/platform-source-contract.dynamic-web.toml`。基线 `903be6d0`，分支
`feat/dynamic-discovery-sources`。本轮不增加 NGA 专用适配器。

## 用户流程

1. 在「聊聊口味」说明网站／Feed URL、希望发现的内容、频率和份额；缺少必要条件时补问。
2. 普通网页用托管 Ego Lite 观察并生成受限流程；Feed 用 HTTP。需要登录时提供接管页，
   不在聊天里收集密码或 Cookie。
3. 实际试采后检查样例；可继续用自然语言纠正范围。试采失败不会启用来源。
4. 点击启用确认卡的「批准并执行」，才发布独立来源和定时流程。
5. 定时发现经过正常候选入队、去重、模型评估与入池；采到内容不等于全部成为推荐。
6. 设置页管理来源名称、独立份额、采集间隔、启停与运行记录。

## 发现的问题与修复

1. 首次真实聊天得到 `needs_details`：读取到 403 访客过渡页，样例为零。
   同一原生采集会话的即时 snapshot 是过渡页，2 秒后无登录自动变成正常列表；
   没有主页面跳转拦截。新增协议回归先失败，证明旧实现会过早返回。
   修复为文档完成后稳定 1.5 秒再返回，URL／loader 变化重新计时，仍受 30 秒导航预算
   和原有请求／重定向访问规则约束；覆盖后续 loader 在首次轮询前已提交的情况。
   另修复自动跳转后仍保留旧 403 文档诊断的问题：最终主文档 2xx 清除过期文档错误，
   不清除脚本失败和访问拦截。原生协议回归覆盖 403→200 且保留 Script 404。
2. 正常列表最初丢失带 ID 链接的 class 信息，模型生成不存在的链接选择器，试采失败。
   增加实际 `class_selector` 后，模型又明确指出观察仅有置顶区。
   观察器现从最多 500 个可见表格行／文章容器中保留前 4 个、分散取其余最多 12 个及首尾链接，
   总观察仍最多 100 个元素。两种遗漏都有执行真实 DOM reader 的失败→通过回归。
   这只调整观察，不提高实际采集条数，也不硬编码 NGA 选择器。
   首版均匀抽样因列表前还有布局表格而漏掉第一条公告；加入保留列表头部的回归。
3. 一轮技术试采成功但样例含公告／专楼。没有批准该草稿；从页面拒绝后通过自然语言
   进一步描述排除范围。首次「拒绝」只展开原因框，点击「确认拒绝」才实际提交。
   这说明选择器能运行不等于语义范围完全正确，必须检查真实样例，不能只相信回复中的
   “已排除”声明。
   后续严格排除高亮、公告、专楼的计划仍未稳定达标；生成提示补充反例检查后，
   模型会明确拒绝证据不足的计划，但本轮不宣称复杂语义过滤已修复。
   因用户本次仅要求验证 NGA 建源，最终另以明确的“板块帖子，允许置顶／高亮／专楼”
   范围完成业务链路；严格过滤场景保留为未通过项。
