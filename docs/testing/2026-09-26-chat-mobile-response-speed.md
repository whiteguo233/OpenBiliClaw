五条无需工具的简单请求中位耗时由 **3.115s → 1.644s**，本次样本约减少 **47%**。算术实际回复“5。”，致谢回复“不客气。”；画像仍真实调用 `get_profile` 后回答。单次回复长短及上游耗时会波动，本轮没有通过截断文本、降低所有任务的 token / reasoning / 多跳预算来制造速度提升。

根因是所有 Agent 角色继承“苏格拉底式追问”。Agent 现在按当前请求决定深度：寒暄简答、事实直接给结果、尊重长度要求；复杂任务保持工具链和分析能力，口味探寻师保留自己的访谈规则。原 CLI / legacy 的默认对话风格保持。

## 配置审批加速

手机 UI 实际批准模型生成的 `agent.loop_max_steps` 63 → 62 卡片，批准到后端 `executed` 为 **0.029653 秒**；磁盘值正确，重复批准不重执行。另一轮真实模型生成 62 → 63 卡片，后台 LLM 请求活跃时批准，执行为 **0.027842 秒**，前后活跃请求均为 1、事件通道未暂停。上一轮同类配置走全量热重载曾耗时 577 秒。

现在只有系统管家批准的 `loop_enabled`、`loop_max_steps`、`tool_result_max_chars`、`session_title_enabled`、`task_max_steps` 五项独立设置可局部生效。仍沿用原配置事务、最后有效配置、审批审计及结果回放；完整配置还必须与当前实例匹配。构造新 loop 后同步发布，在途回合继续持有原 loop，画像学习所有者保持。

普通设置保存、其他字段及需要重启的修订仍完整重载。Cookie 文件不属于 Config 对象，因此特别保留普通设置的重建要求；队列合并和失败修订接替也继承这一要求。14 项新增回归包含三种 Cookie 外部依赖场景，防止“配置看起来相等、客户端仍用旧凭据”的误判。

## 移动端真实浏览器验收

使用真实 Chromium 移动视口与真实服务请求，覆盖 390×844 和 320×568；键盘覆盖分别以 390×400 窗口和仅缩小 visualViewport 模拟。**未使用物理 iPhone / Android 设备，不能替代真机 Safari 验收。**

| 场景 | 结果 |
|---|---|
| 点击发送 | 立即出现用户气泡和等待状态；原先缺少 scope 导致被过滤 |
| 回复期间继续输入 | 原 textarea 节点、5 行草稿、112px 高度、选区及焦点保持 |
| 回复期间阅读旧消息 | 完成与迟到历史响应均保留滚动位置，不强制到底部 |
| 键盘占用高度 | 400px 可视高度下聊天区 14px → 178px；发送按钮完整可点击 |
| visualViewport 单独变化 | 布局高度 844 / 可视高度 400 时正文调整到 400，输入底部 378；恢复后样式复原 |
| 小屏与角色 | 320×568 无横向溢出；追番顾问选择及刷新保留；切回原会话恢复口味伙伴 |
| 短暂断网 | 发送后离线 1.2 秒再联机，原 turn 恢复；刷新后没有重复消息 |
| 建 turn 请求延迟 | 真实 POST 增加 4 秒传输延迟，乐观气泡继续可见且不重复 |
| 配置批准 | 手机实际点击批准，显示“已批准并执行”，待审批数归零 |
| 旧历史简单问候 | 实际回复“在。”，2.487 秒（含截图开销），不复制历史时间标签 |

真实复测中还发现模型会复制历史时间前缀，已添加上下文时间仅供理解的规则；用户明确问时间或要求原样引用时仍正常回答，不用正则删除用户内容。

复杂请求保留能力：真实“查询推荐 → 用查询返回的内容 ID 保存本地稍后再看”工具链成功，8.4 秒完成两个工具调用，回复按要求一句话说明结果。没有向平台账号写入。
