# OpenBiliClaw v0.3.239 发布记录

[聚合下载页](https://github.com/whiteguo233/OpenBiliClaw/releases/tag/openbiliclaw-v0.3.239) 汇总本版源码、桌面和扩展。应用提交 `3180dd47`（固定运行时目录的 pin 提交）直接合入 main，backend、desktop、extension 与 openbiliclaw 四个标签指向该提交。

`[skip ci]` 提交上的标签推送不会自动运行发布，四条工作流按既有惯例以各版本标签显式 dispatch，未重打标签。

## 修复回顾

首次尝试的 0.3.238 未发布任何资产：固定目录 `sponsored-runtime-2026-11-10.1` 的 manifest 兼容窗口严格为 0.3.237，桌面 PyInstaller 与 Docker 在 `stage_runtime_bundle` 阶段被 `verify_bundle` 以「免费模型组件与当前版本或平台不兼容」拒绝，extension 另因 GitHub macOS runner 容量不足被取消。空发行页与四个标签已删除，0.3.237 恢复为 Latest，随后以 0.3.239 重做本版。

## 签名运行时

固定目录更新为 [sponsored-runtime-2026-11-16.1](https://github.com/whiteguo233/OpenBiliClaw/releases/tag/sponsored-runtime-2026-11-16.1)，manifest 兼容窗口 `core_min = core_max = 0.3.239`，Core 契约快照 `0dfc2c8b`。

运行时本身只做依赖修补：`cargo audit` 新披露的 RUSTSEC-2026-0486 让 `rustix` 1.1.5 变成阻断项，升级到 1.1.6 后五平台构建恢复。协议、策略、模型、额度、密钥 epoch 与到期时间均不变。

- 构建：[release 43751705127](https://github.com/whiteguo233/OpenBiliClaw-sponsored-runtime/actions/runs/43751705127)，五个平台全部成功
- 运行时源码：`b5a81093a752e93f3251141de48d099afeb50fd4`
- Mac 公证：`45a9e942-14f5-40ab-a2aa-71f8416fd96c`（arm64）、`0776c0e5-9b0e-4dd3-8328-33865cd69d96`（x86_64），两者均 Accepted
- 目录经 `tools/export_catalog.py` 对五个归档静态验签后生成，上传后 GitHub 回读的 SHA-256 与目录逐项一致

发布前在 Core 本机跑通 `python -m openbiliclaw.runtime.sponsored_bundle --stage`，即 Docker 与 Windows 构建失败的同一条门禁；暂存后的 manifest 为 `macos-notarized`。

## 桌面安装包

`desktop-v0.3.239` 与聚合页均已附 Windows 普通版、Windows 内置向量版、macOS arm64 普通版与内置向量版。Windows 安装器包含本版主打的「选择目标位置」修复：交互式安装与升级都显示目录页，升级预填原目录，换目录须先卸载。
