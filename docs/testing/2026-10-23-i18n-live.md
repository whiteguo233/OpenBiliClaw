## 真实聊天结果

三个场景均发送同一句简体中文问题，没有在问题中指定输出语言：

> 请用两句简短的话介绍图书馆里可以做什么，提到读书和学习。

先保存语言，等待 `/api/config/apply-status` 报告已应用，再调用生产 `/api/chat`。
英文首次选择通过真实设置页面完成；后续两次切换通过真实配置 HTTP 接口完成。

| 配置语言 | HTTP / 约耗时 | 实际回复节选 | 用量账本中的成功聊天模型 |
| --- | --- | --- | --- |
| `en` | 200 / 4.20 秒 | “In a library, you can borrow and read books…” | `deepseek-v4-flash` |
| `zh-Hant` | 200 / 5.50 秒 | 「圖書館是讀書的好地方……這裡也適合學習」 | `sensenova-6.8-flash-lite` |
| `zh-Hans` | 200 / 5.31 秒 | 「图书馆里可以安静地读书……找个角落学习、查资料」 | `sensenova-6.8-flash-lite` |

繁体回复包含 `圖 / 書 / 這 / 裡 / 學 / 習` 等可区分字符。简体与英文也符合配置。
这是每种语言一次短回复的抽查，不能保证所有模型、长对话和推荐理由均无漏译。

主通道在后两次聊天时出现限流，生产日志记录 `marked rate-limited` 与 `trying next fallback`；
回复来自已有回退链。配置中的实例、模型和顺序没有因语言保存而改变，不能把后两次成功归因于 DeepSeek。
SQLite 记录 3 次聊天和 3 次后台洞察成功，共 6 条成功用量；另观察到 2 次主通道限流事件。
用量账本不是全部 HTTP 尝试的抓包记录，不据此宣称只发送了 6 次远端请求。
