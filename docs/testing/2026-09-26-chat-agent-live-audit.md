# 聊一聊真实环境验收（2026-09-26）

基线为 main `1253a0a8`，修复分支 `fix/chat-agent-live-audit`。使用现有真实模型配置、SQLite 在线备份和画像/记忆副本；本地收藏、反馈、审批写入仅用于测试实例。未向平台账号提交收藏、点赞或消息。主工作区已有文档改动保持不变。

## 复现与修复

| 问题 | 证据 | 修复 |
|---|---|---|
| 查询之后无法保存或反馈 | 浏览器真实请求查到推荐，但模型明确报告返回值没有 content_id / recommendation_id | 查询输出携带精确内容定位信息，推荐历史携带真实记录 ID |
| 点赞工具不可用 | 指定真实 recommendation_id 仍返回 `event_ingress 未初始化` | 启动与热重载绑定统一反馈入口 |
| 会话串线 | 回归测试复现迟到历史覆盖新会话、旧流覆盖新角色；模型历史跨会话混入 | 三端请求代次/来源会话校验，后端按 session_id 恢复短期历史 |
| 断流误成功、重试重复执行 | 三端仅有 final 而无 done 的流被当成功；同 turn 重试重复调用工具 | 要求终端 done；API 独立持有原执行任务，终态重试重放 |
| 绑定学习和审批结果丢失 | 流式缺少 canonical binding / 对象副作用，终态批量覆盖事件 | binding 贯穿 prompt 与学习，逐事件持久化及一次完成副作用 |
| 确认列表阻塞整个服务 | 319 条真实待确认下单请求约 4.66 秒，禁用后台工作仍复现；重复轮询使其他接口超时 | 等价相似度上界剪枝、按精确输入缓存、批量查询已打开确认 |
| 审批卡不生成、拒绝理由丢失 | 系统管家口头要求再次确认；轮询重绘清空正在编辑的理由 | 明确请求先生成审批卡；执行仍须批准，三端保留编辑状态 |
| 热重载后审批退回已批准 | 临时路径别名下实际配置已 applied，但审批列表回退 approved | 按规范化数据目录识别同一审批文件，热重载继续复用唯一存储实例 |
| 已批准配置被后续回滚覆盖 | Agent 单独持久化未推进设置队列的 last-good 基线 | 通过统一配置事务队列应用，实际成功后更新回滚基线 |
| 无效配置仍被批准写盘 | 临时真实 TOML 接受不存在的 provider，运行时校验随后失败 | 写盘前验证，失败回滚并标记工具失败；审批前校验参数 |

## 环境说明

初次真实浏览器复现运行于本机已有 AppReview 实例；随后发现其自重启服务占用 18420，固定修复验收改到确认空闲的 **127.0.0.1:18429**，并核对监听进程及其打开的数据库路径。两套数据分开，不把服务切换造成的 404 当作产品缺陷。

完整数据副本有 319 条待聊确认。后台恢复与前端轮询下曾出现明显 CPU 饥饿，另用独立副本定位；独立性能采样定位到 `difflib.SequenceMatcher` 的全量模糊去重与逐项 SQLite 查询，详见最终复测结果。

## 验证方法

- 浏览器：Playwright CLI 操作桌面 Web 与 390×844 移动 Web；真实 Chromium 加载构建后的 unpacked 扩展 popup。
- 真实请求：创建 durable turn → agent SSE → 实际模型工具调用 → 检查 SQLite 状态、事件与本地保存结果。
- 生命周期：审批拒绝/批准/幂等、配置热重载后继续聊天、后台任务完成/取消、HTTP 中途断开后完成及同 turn 重试。
- 自动化：全仓 `pytest`、`ruff check src/ tests/`、`mypy src/`，前端 JavaScript 回归及扩展构建/完整测试。

截图及包含真实内容的原始请求记录保存在本地 `output/playwright/` / 临时文件，不提交到仓库。

## 真实链路与性能结果

- 桌面：真实模型查询推荐池与观看历史，使用查询结果中的精确 ID 保存本地稍后再看并提交推荐反馈；4 个工具步骤成功，刷新后过程完整回放。
- 移动：390×844 视口完成画像查询，刷新后回放；实际拒绝一项配置审批；另一张卡片的拒绝理由跨轮询保留后取消拒绝。
- 内容源：真实模型从空订阅开始创建明确 E2E 源，卡片批准后落库；再次查询取得系统生成的真实 ID，禁用卡片批准后状态为 disabled，重复批准不增加审计记录。最终测试源保持禁用，未触发外部抓取。
- 工具矩阵补测：真实调用核心记忆、历史搜索、候选池查询均成功；在隔离副本 event 层写入明确测试标记并读回，两个工具均成功。
- 扩展 popup：加载实际构建产物，完成画像查询、回放与角色切换；真实 DOM 重绘后拒绝理由文本、焦点和选区保留。
- 配置审批：真实模型生成审批卡，移动端批准后进入执行，最终显示“已批准并执行”；磁盘与实际 `get_config` 均读到 63，重复批准返回 `already_executed=true`。热重载后的真实反馈工具成功落库（3.5 秒），证明反馈入口重新接线。
- 生命周期：只读后台任务完成、另一任务取消；在收到工具结果后断开 SSE，原 turn 继续完成，再以相同 turn 重试，持久化事件未增加，未重复工具执行。
- 确认列表：相同 319 条真实候选，修复前后完整 JSON 相同；修复前约 4.5–4.66 秒，修复后冷请求 0.862 秒、热请求 29–32 毫秒；三端同时打开时约 42–45 毫秒，健康检查约 18 毫秒，角色列表约 7 毫秒。

网络中断保护保证同一服务进程存活时沿用原执行；进程在外部副作用和落库之间崩溃仍不具备分布式 exactly-once 保证。重启/切换测试服务造成的连接拒绝另行排除；未观察到三端 JavaScript ReferenceError、TypeError 或 SyntaxError。

## 配置热重载的实际等待

完整后台恢复模式下，批准到执行完成耗时 **577 秒（9 分 37 秒）**；等待的是正在进行的真实画像/反馈学习，不是审批 Future 互锁。原配置允许单个 LLM 请求等待 1,200 秒，安全排空预算为 25 分钟。等待期间新聊天仍在 7.04 秒内完成真实 `get_config` 调用；配置实际完成前返回旧值 64，完成后返回新值 63。

另用独立副本关闭反馈恢复，保留真实对话与学习请求，配置应用还要等待已启动的对话学习。说明配置完成速度受后台真实请求影响，不能承诺点击后立即生效。本轮增加“等待画像/反馈 → 等待当前对话 → 等待对话学习并重建 → 恢复后台”的阶段状态，保留既有安全排空和失败回滚语义。

相对路径与符号链接的审批状态回退另有三种自动化回归，覆盖不同工作目录的项目根解析、配置应用终态、store 实例身份与重复批准幂等。加载修复后，在 `/tmp` → `/private/tmp` 的真实路径别名环境重新调用模型生成新审批卡并批准，86.76 秒后正确落到 `executed`，磁盘目标值为 62，重复批准仍为 `already_executed=true` 且 `queued=false`。最后补跑三种路径与反馈重接线共 4 项检查通过。

验收结束后关闭本轮桌面、移动、扩展专用浏览器和两个隔离测试服务；原有 AppReview 服务保持运行，主工作区已有改动未被覆盖。
