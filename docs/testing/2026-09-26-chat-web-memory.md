# 聊天网页工具与笔记管理验收（2026-09-26）

分支 `feat/chat-web-memory` 基于 `be8c5514`，继承聊天风格与前三轮修复。使用独立
worktree、真实模型配置和真实数据的副本，服务监听 18439。全部笔记、审批与会话
写入仅落测试副本；用户原有 18420 实例及主工作区未提交文档不改动。

## 能力与边界

- 新增 search_web 和 read_webpage，四个内置角色均可按需使用；搜索调用 Exa
  公开 MCP，阅读链接直接取得公开静态正文，不携带登录 Cookie，不执行网页脚本。
- read_memory 可按 key/keyword 查看聊天笔记；write_memory 更正已有项须带完整
  expected_value；delete_memory 经审批并在实际执行时再次校验原值。
- 自动偏好/画像重建保留 agent_notes；JSON 文件锁和原子发布保护并发写入。
  删除只针对指定聊天笔记，不声称擦除历史、自动偏好或画像。
- 最多 8 条/3000 字符的笔记快照按 read_memory 角色权限进入 Agent user context，
  不进入 system、原始消息或学习载荷，后续成功工具结果优先于本轮开头快照。
- 三端复用工具过程、来源链接和审批卡；CLI/OpenClaw legacy 对话本轮未切换
  AgentLoop，不宣称这两个入口拥有新增工具。

这些是实际样本，不是固定延迟保证。首次更正请求暴露旧快照与新工具结果的表达
冲突，模型重复读两次并误说回退；成功写入现在回显新值，快照标明时点，复验只需
一次读和一次写。首次删除回复误说“已批准”，但后台记录始终 pending、没有删除；
增加明确审批状态纪律后，新请求正确说明“尚未执行”。审批卡和服务端执行结果仍是
状态事实来源，不能把语言模型文案当作执行证明。

首次模糊提问“验收专用饮料偏好”也出现先否认、再列出对应饮料的冗长答复：旧数据
含其他验收标记，目标笔记 value 本身只有饮料名。按已保存 key 精确提问的复验给出
正确简答；不把简单场景的一次成功泛化为所有自然语言表述都准确。

插件在实际加载的未打包 Chrome 扩展里调用 read_memory，工具返回完整记录，页面
显示“柠檬水”，durable turn completed。随后手机批准删除，插件再次查询返回空列表，
即使历史仍有旧值，最终答复也正确说明“已不存在”；刷新后回放一致。

手机实测还发现裸来源 URL 只是文本。修复三端共享 Markdown 渲染器后，桌面与手机
既有回复刷新即可显示可点击来源；桌面实际打开 Python 官方文档成功。URL 处理保留
HTML 转义，跳过代码和已有链接，不激活危险协议。320/390px 手机无横向溢出，插件
430px 无横向溢出；重启测试服务期间出现的断连日志不作为稳定运行时前端错误。

## 网络验证

公开 Exa 工具本身真实调用成功，桌面首次请求却得到 ConnectError。检查确认测试
进程继承了 loopback HTTP_PROXY/HTTPS_PROXY，而副本配置 network.mode=system；
独立工具初测采用默认 direct，因此两者路由不同。失败工具返回 ok=false，模型如实
说明未查到、未伪造来源。新增安全异常类型提示，不回显代理 URL、凭据或异常原文。
只将隔离副本显式设为 direct 继续正向验收，工具实现仍尊重用户网络策略。随后桌面
真实请求成功，工具 ok=true、循环未截断，3500 字符完整 JSON 含 5 个官方 URL。
免费公开 MCP 可能限流；本轮没有改动用户原服务的网络配置。

网页读取使用 DNS 解析后的公开 IP 连接和原域名 TLS SNI/证书验证。真实读取
IANA example-domains 为 795 字、0.919 秒，example.com 为 127 字、0.720 秒。
覆盖私网/本机/IPv6 过渡地址、混合 DNS、重定向绕过、TLS 域名、体积、压缩、
超时、登录页、危险协议与完整 JSON 预算；不自动绕过登录或改走用户浏览器。
