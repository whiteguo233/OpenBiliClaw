# 产品演示素材指南

README 和官网先展示推荐结果，再解释推荐理由与反馈，最后引导安装。素材也按这条顺序组织。
本页记录已有素材、后续录制分镜和维护要求；录制计划不表示视频已经完成。

## 现有素材与用途

素材位于 [`docs/images/`](images/)。以下文件已经存在，使用前仍需核对画面与当前版本是否一致。

| 素材 | 内容 | 适用位置 |
|---|---|---|
| `desktop-home.png`、`desktop-cards.png` | 桌面推荐页与内容卡片 | README / 官网主图、推荐场景 |
| `screenshot-recommend.png`、`screenshot-recommend-feedback.png` | 插件推荐页与反馈界面 | 推荐理由、反馈场景 |
| `desktop-profile.png`、`screenshot-profile-*.png` | 桌面 / 插件画像 | 解释偏好与画像，按需选一张 |
| `screenshot-chat.png`、`screenshot-interest-probe.png` | 对话与兴趣试探 | 对话反馈、理解偏好的补充展示 |
| `mobile-recommend.png`、`mobile-profile.png`、`mobile-chat.png` | 手机 Web 推荐、画像与对话 | 手机 Web 客户端介绍；不能标成 Flutter 原生 App |
| `hero-demo.png` | 从截图制作的流程说明拼图 | 流程概览；不是一张完整产品界面 |
| `hero-demo-zh.gif`、`hero-demo-en.gif` | 四张说明画面轮播，每张约 2.5 秒 | 可标为「功能概览」，不能称为操作实录 |
| `hero-demo.gif` | 英文 GIF 的兼容副本 | 历史引用，新增引用优先用带语言的文件名 |
| `social-preview-zh.png`、`social-preview-en.png` | 社交分享卡片 | Open Graph / 分享预览 |
| `chrome-web-store/` | 商店宣传素材及其演示数据截图 | 商店展示；不能替换官网、README 的真实产品截图 |

GIF 由 [`build_readme_hero_demo.py`](../scripts/build_readme_hero_demo.py) 将已提交截图与说明文字合成，
没有连续鼠标操作，也不能证明推荐生成速度或反馈后的学习效果。旧轮播仍含早期说明文案，
重新使用前需逐帧复核；新首页优先复用静态产品截图。当前没有已交付的产品演示视频，
不要添加无目标链接的播放按钮、虚构视频封面或标成「观看演示」的截图跳转。

## 补充素材的顺序

1. **清晰主图**：优先选可读的桌面推荐画面，保留平台来源和推荐理由。不要用多个缩小界面塞满首屏。
2. **工作方式示意图**：说明内容来源 / 浏览器、电脑上的后端与存储、各客户端及可选模型调用。图中区分本机数据与发往用户所选模型服务的内容，并与架构文档同步。
3. **15–25 秒操作实录 GIF**：展示一个完整动作链，供 GitHub README 使用。
4. **60–90 秒产品演示视频**：展示结果、理由与反馈，放在官网，并从 README 的视频封面链接过去。
5. **独立安装教程**：产品演示稳定后再录。安装页面变化较快，教程不混入产品主视频，以便分别更新。

## 15–25 秒 GIF 分镜

| 时间 | 画面与动作 | 要让用户理解的内容 |
|---|---|---|
| 0–5 秒 | 停留在一条清楚显示来源、标题和推荐理由的卡片上 | 推荐什么、为什么推荐 |
| 5–12 秒 | 打开反馈入口，选择「不感兴趣」或填写具体反馈 | 可以纠正推荐 |
| 12–20 秒 | 提交反馈并等待真实确认，停留在确认状态 | 反馈已收到，动作完成 |
| 20–25 秒（可选） | 回到推荐页，留出阅读时间后结束 | 如何继续使用 |

只展示当前版本实际存在的控件和结果。收到反馈的确认不等于新一轮发现、画像更新和推荐全部完成；
不要用剪辑把后续推荐变化拼成即时效果。若要展示稍后的结果，用字幕明确标记「下一轮推荐后」或实际经过时间。

## 60–90 秒视频分镜

| 时间 | 内容 | 字幕重点 |
|---|---|---|
| 0–10 秒 | 直接展示推荐页，突出一条值得打开的内容 | 跨平台内容放在一起，先看到结果 |
| 10–25 秒 | 停留并读懂推荐理由，打开原文或原视频 | 用户能判断推荐是否适合自己 |
| 25–45 秒 | 给出一次具体反馈，展示系统真实确认 | 不感兴趣、反馈或对话中的偏好表达 |
| 45–60 秒 | 展示画像或一段简短对话，解释偏好如何积累 | 学习是逐步发生的，避免承诺即时重训 |
| 60–75 秒 | 简单工作方式与数据去向图 | 本地优先；云端模型按用户配置调用 |
| 75–90 秒 | 展示安装入口及三项前置条件 | 桌面后端 + 插件；配置模型、来源并初始化 |

需要更短版本时缩短停留时间，仍保留真实确认和数据边界。视频不自动播放声音；提供可手动播放的控件、
清楚的时长、静态封面和中英字幕。演示字幕与安装指南使用同一套名称。

## 录制与真实性

README 与官网的截图、录屏必须来自**真实运行的 OpenBiliClaw profile**。先在隔离的数据目录和浏览器
配置中准备可公开的内容，再启动真实后端与对应客户端，记录版本 / commit、日期、平台、界面语言和录制范围。
不要直接录制个人日常浏览器或含私人历史的 profile；不要把个人凭据或真实用户数据库提交到仓库。

[`capture_chrome_webstore_ui.py`](../scripts/capture_chrome_webstore_ui.py) 用固定本地演示数据和临时浏览器
profile 截取商店素材，并拦截外部请求。其 `capture()` 明确拒绝 `docs_output_dir`：

> demo fixture captures must not replace README or GitHub Pages screenshots; capture those from a real running OpenBiliClaw profile

不要绕过这条限制，也不要把商店 fixture API 的固定返回伪装成真实推荐或真实学习效果。若需要说明尚未
实现的设计，独立标为「设计示意」，放在相应设计文档中，不混入产品体验区。

可以裁剪空白、遮盖敏感字段、加指针强调和剪去等待；不能改写 UI 状态、推荐理由、响应结果或错误提示。
剪辑影响时间判断时需加「已省略等待」等字幕。推荐内容属于外部平台，保留必要的来源标识，
不要用他人视频整段替代自己的操作过程。

## 隐私检查

录制前关闭桌面通知、个人标签页和自动填充。录制后逐帧检查账号昵称 / 头像、浏览历史、对话、画像、
API Key、Cookie、密码、二维码、Tailnet 入网链接、设备地址、文件路径和日志。首选在录制环境里
移除不适合公开的数据；必须遮盖时确保每一帧和封面都处理到，不能只处理开头。

数据流说明统一为：画像、推荐历史等数据默认保存在本机；使用云端 LLM 或 embedding 服务时，
必要内容会发送给用户选择的服务商。不要用「100% 本地」或「所有数据永不离开设备」概括所有配置。
完整边界见[隐私政策](privacy.md)。

## 输出与验收

以下为压缩目标，画面文字可读性优先：

- 主图优先保留 1440–1600 像素宽原图，明确 `width` / `height` 与描述性 alt；网站按显示尺寸提供压缩版本。
- GIF 建议 960–1280 像素宽、10–12 fps、15–25 秒，争取控制在 5 MB 内；超出时先缩短停留和录制范围，避免把正文压到无法阅读。
- 视频建议 1920×1080、30 fps、H.264 MP4，保留高质量母版；官网按需加载，完整视频可使用稳定的托管链接。
- 字幕分别交付中文、英文 SRT / VTT；GitHub GIF 无字幕轨，必要文字需直接可见，同时在正文提供动作说明。
- 官网优先静态封面，尊重减少动态效果的系统设置。所有媒体保留无需播放也能理解的文字描述。
- 在 GitHub README 和官网桌面、手机实际检查图片比例、推荐理由可读性、字幕遮挡、链接、加载体积及键盘操作。

每次替换素材，同步检查 README 中英文版、官网默认中文与英文内容、分享卡片，以及
[主页与 SEO 维护指南](seo.md) 中的 metadata / sitemap 引用。只有素材完成隐私与真实性检查、
播放地址实际可用后，才将首页按钮改为「观看演示」。
