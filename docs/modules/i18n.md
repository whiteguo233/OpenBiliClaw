# 多语言（i18n）

> 状态：**多语言基础设施已落地**（简体中文 / 繁體中文・台灣 / English 三端可选）。
> 关联 issue：[#305](https://github.com/whiteguo233/OpenBiliClaw/issues/305)。

## 目标与边界

OpenBiliClaw 的界面、CLI 与模型输出统一由 `[general].language` 驱动，一次切换同时影响：

- 桌面 Web（`/web`）、移动 Web（`/m`）、首次设置向导（`/setup`）
- 浏览器插件侧边栏
- 后端 CLI 的用户可见输出
- 新生成的聊天回复、推荐理由等自然语言内容

**不翻译**：用户内容、平台原文（视频标题 / 简介 / 动态正文）、历史聊天与已生成的推荐/画像文本、
JSON key、枚举、ID、URL、平台原生搜索词。历史内容保持生成时的语言，切换语言不会批量重译或重算。

## 语言契约

规范 id 为 BCP-47 script-qualified：

| id | 含义 | 兼容别名（读入时规范化） |
|---|---|---|
| `zh-Hans` | 简体中文（默认） | `zh`、`zh-CN`、`zh-SG`、`zh-Hans-*` |
| `zh-Hant` | 繁體中文（台灣用語） | `zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant-*` |
| `en` | English | `en-US`、`en-GB`、`en-AU` 等 `en-*` |

`config.toml` 允许保留旧值（如 `zh`、`en-US`），读取时由
`openbiliclaw.i18n.resolve_locale()` 解析；`PUT /api/config` 落盘前会把已知别名规范化为上表 id，
未知语言直接 400 拒绝（`unsupported_language`），不会静默变成默认语言。

回退链：`zh-Hant → zh-Hans → en`，`en → zh-Hans`。简体中文是源语言，因此任何未翻译条目至少
回退到简体，不会出现空白文案。

## 代码结构

```text
src/openbiliclaw/i18n/
├── locales.py          # 规范 locale、别名、回退链、展示名、HTML lang
├── catalog.py          # 语义消息目录加载 + Translator（{param} 插值）
├── output_language.py  # 模型输出语言指令（只进 user prompt）
├── catalogs/           # Python 侧语义目录：zh-Hans（源）/ zh-Hant（生成）/ en（手写）
│   ├── zh-Hans.json
│   ├── zh-Hant.json
│   └── en.json
└── ui/                 # 客户端 UI 目录：key = 简体中文原文
    ├── zh-Hans.json    # 全量清单（源）：messages + patterns
    ├── zh-Hant.json    # OpenCC s2twp 生成（含 patterns）
    └── en.json         # 人工 / 模型翻译，测试要求 100% 覆盖（含 patterns）
```

### 客户端 UI：源文即 key

Web 与插件是约 7 万行 vanilla JS/HTML，文案以内联简体中文写成。为了不改写几千处调用点，
`src/openbiliclaw/web/shared/i18n.js` 按**渲染后的 DOM 文本精确匹配**查表翻译：

- key 是简体中文原文（由 `scripts/build_i18n_catalogs.py` 扫描 HTML 文本节点、可翻译属性
  （`placeholder` / `title` / `aria-label` / `alt`）与 JS 字符串字面量生成）；
- 只翻译与目录完全一致的文本，模型输出、视频标题、用户输入天然不会命中；
- 需要保护的内容区加 `data-i18n-skip`；语言选择器本身用 `data-i18n-skip` 保持各语言自称；
- 节点被重新渲染时按最新文本重新查表，可随时切回简体；
- `MutationObserver` 覆盖异步渲染的列表 / 面板以及动态 `title`、`placeholder`、`aria-label`、`alt`；切回简体时恢复源文。
- 并发切换以最后一次选择为准；目录请求失败只临时回退，下次切换会重新请求。

| 客户端能力 | 实现 |
|---|---|
| 默认简体启动 | 内置 `zh-Hans` 目录全部为原文映射；直接显示源文，不下载目录、不遍历 DOM、不启动翻译观察器 |
| 实时切换与回退 | 第一次切换译文时记录源文；切回简体恢复文字与属性，之后重新插入的旧译文节点也会恢复 |
| 目录并发与故障 | 同一语言在途请求合并；较早请求不能覆盖较新的选择；失败、空或非法条目不写缓存，可再次切换重试 |

共享 API `OpenBiliClawI18n.init({ locale, basePath, fetchCatalog, onChange })`、
`setLocale(locale)`、`apply(root)` 与格式化方法保持不变。内置目录路径为 `/i18n/ui/`；
自定义 `fetchCatalog` 或其他 `basePath` 仍加载简体目录并应用其覆盖值，不假设自定义文案是原文。
`init()` 更换目录来源时清空对应缓存；并发 `init()` / `setLocale()` 以最后发起的语言选择为准。

**模式目录（插值文案）**：模板拼接出来的整句（如 `已修改 1 项`、`模型：deepseek-v4-flash`）无法靠
整句 key 命中，因此目录额外有 `patterns`：

```json
"patterns": {
  "已修改 {0} 项，未保存": "Modified {0} item(s), unsaved",
  "模型：{0}": "Model: {0}",
  "{0} 分钟前": "{0} minutes ago"
}
```

运行时把每个模式编译成 `^字面量(.*?)字面量$` 的锚定正则（`{1}`、`{2}` 依次成为捕获组），
先按字面量长度从长到短匹配；命中后用捕获值替换译文里的占位符。key 始终是简体源模式（DOM 切换
语言后仍用记录的 source 匹配），`zh-Hant` 的 value 由 OpenCC 生成、`en` 需人工翻译，测试强制
key 集合与占位符集合完全一致。
数字单位/日期类模式（`{0}万`、`{0}月{1}日`）不进入目录：它们是计算而不是文本，由运行时的
`formatCount()` / `formatShortDate()` 按 locale 生成——英文 `331K` / `Sep 5`，繁体 `33.1萬` / `9月5日`，
简体 `33.1万` / `9月5日`；桌面、移动 Web 与插件原有的 `formatCountCn` / 日期格式化都委托给这两个函数。
切换语言后已渲染的数字与日期不会原地重排，下一次渲染（刷新、换一批、切页）时使用新格式。

目录由后端静态挂载：`GET /i18n/ui/<locale>.json`。插件在构建时把同一份目录复制到
`popup/locales/`，因此后端不可达时侧边栏自身的界面仍然可以本地化。桌面安装包
（PyInstaller）在 `packaging/openbiliclaw.spec` 里把 `openbiliclaw/i18n` 一并打进
`datas`，与 `web/` 同级；wheel 由 hatchling 自动包含，Docker 直接复制 `src/`，三种
安装模式都带上目录（`tests/test_i18n.py::TestClientWiring` 守护 spec）。

### Python 侧：语义 key

CLI / API / 提示词用稳定 key（如 `cli.config_show.title`）查 `catalogs/<locale>.json`，
支持 `{name}` 插值；缺失 key 返回 key 本身，便于在输出里发现缺口。

导演/Jev 主线集成同步覆盖 Jev 共用设置表单、移动评估器提示和 `config-show` 的模型/容量/凭据状态；
仅翻译标签与安全状态，不翻译模型 ID、URL、Token 或用户内容。动态数值保持原占位符，繁体目录由同一构建脚本生成。

### 模型输出语言

按仓库的 prompt-cache 约束，**system prompt 保持字节静态**，locale 以
`<output_language>` 指令块附加在 **user prompt 末尾**（`append_output_language()`）。
已接入：聊天（`LLMService` / `SocraticDialogue`）、推荐理由（单条与批量表达）。
内部评估、抽取、关键词规划等不面向用户阅读的提示词保持单一模板，避免行为漂移。

**繁體字符约束**：中文 system prompt 会让模型默认输出简体，仅写「Traditional Chinese」实测不够
（2026-10-19 真实 provider 首轮回复仍是简体）。因此 `zh-Hant` 指令额外要求「只用繁體字、不得出现
简体字」并给出 `說/说`、`這/这`、`點/点`、`裡/里` 对照；强化后同一模型同一问题返回全繁體。
`tests/test_i18n.py` 固定该规则只出现在 `zh-Hant` 指令里。

## 配置与 API

- `[general].language`：**所有端共用的默认语言**，桌面 / 移动 / 插件分别在各自的配置页
  「设置 → 通用 → 默认语言」里修改；`zh-Hans` / `zh-Hant` / `en`（旧值自动规范化），见
  [config 模块文档](config.md)。
- `GET /api/i18n/locales`：返回默认语言、当前语言与可选语言（含各语言自称）。
- `PUT /api/config`：`language` 落盘前校验；未知值返回
  `400 {"error": "unsupported_language", "value": ..., "supported": [...]}`。
- `GET /api/config`：`language` 返回规范化 id，客户端据此切换界面。

## CLI

```bash
openbiliclaw language                    # 查看当前语言与可选值
openbiliclaw language zh-Hant            # 切换（写回 config.toml）
OPENBILICLAW_LANG=en openbiliclaw ...    # 单次覆盖（不写配置）
```

`cli_i18n.resolve_cli_locale()` 的优先级：`OPENBILICLAW_LANG` / `OPENBILICLAW_LANGUAGE`
→ `config.toml` → `zh-Hans`。`config-show` 的标题、字段名与开关值是首批本地化的 CLI 输出。

## 初始化语言选择（2026-10-23）

| 入口 | 已实现行为 |
| --- | --- |
| `openbiliclaw init` | 交互终端先选择简体 / 繁体 / English，再进入模型与认证检查；默认当前语言，支持编号或 locale / 兼容别名 |
| `openbiliclaw init --language en` | 不提问，规范化后写入 `[general].language`；非法值退出 2，非交互且未指定时保留配置 |
| 一键安装（本地 / Docker） | `agent_bootstrap.py --interactive-confirm` 在 LLM 之前选择语言；`--language {zh-Hans,zh-Hant,en}` 可显式指定；依赖安装前即可执行 |
| 桌面安装包 `/setup/` | 页头常驻自称语言菜单；保存失败有可见提示，后续配置保存 / 初始化会等待语言保存并可重试 |
| 桌面 Web / 移动 Web / 插件 | 共用后端语言；现有通用设置选择器继续有效，共享运行时修复随插件构建复制 |

选择持久化后用于后续界面与模型输出；不等于所有旧 CLI / 安装器日志已经翻译。
CLI 环境变量的单次覆盖优先级保持不变。`cli_i18n.reset_cli_locale_cache()` 在持久化选择后
清空进程缓存，避免后续 CLI 翻译继续使用旧配置。

`/setup/` 按顺序提交语言写请求；较晚返回的配置预填不能覆盖用户已经做出的选择。
语言菜单样式同时适用于桌面和手机，选项始终显示 `简体中文 / 繁體中文 / English`。

本次审计发现的剩余范围：CLI `--help` 和大量历史运行期提示仍是中文，一键安装器的多数日志
仍是英文；扩展后台 badge / 通知文案不经过 DOM 翻译器，不能仅凭 UI 目录覆盖率认定已本地化。
后端动态错误说明与拼接文案也需要逐个运行场景核对。已保存的画像、推荐、聊天和平台原文
属于明确保留原文的内容，不算漏译。

## 新增语言清单

1. 在 `i18n/locales.py` 的 `SUPPORTED_LOCALES` / 展示名 / 别名表加入新 locale。
2. 生成简体源清单：`python scripts/build_i18n_catalogs.py`。
3. 翻译 `i18n/ui/<locale>.json`（缺条目会回退到简体；测试要求 100% 覆盖才通过）。
4. 补 `i18n/catalogs/<locale>.json` 语义目录（与 `zh-Hans.json` key 对齐）。
5. 如新语言书写方向或字体有差异，补前端 CSS（目前仅 LTR）。
6. 跑 `pytest tests/test_i18n.py`、`scripts/build_i18n_catalogs.py --check`。

## 已知限制 / 后续

- 已渲染的数字/日期在语言切换后保持旧格式，直到下一次渲染；如需立即重排需要各端触发一次重绘。
- Typer 的命令与参数 `--help` 在 import 时构建，仍是中文；`config-show`、语言选择等已接入的运行期输出已本地化，其余历史命令仍有中文提示。
- 画像正文、洞察等由模型生成并持久化的内容保留生成时语言，不在切换时自动重建（避免额外模型开销）。
- `zh-HK` / `zh-MO` 目前共用台湾用语目录；后续可拆 `zh-HK` 目录。
- 规划中的 Flutter 原生客户端需按同一 locale 契约接入（独立仓库）。
