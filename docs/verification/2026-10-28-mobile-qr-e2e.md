# 手机二维码真实环境复测（2026-10-28）

本轮仅操作模拟器，没有使用用户的实体手机。结论按网络请求、原生解码、相机回调和网页渲染分别记录；接口成功不等于扫码全链路成功。

## 后端与二维码来源

- 独立 worktree `codex/mobile-network-qr`，后端代码 `c3a0489`。正常 CLI 启动，无 HTTP mock、组件注入或 TestClient。
- SQLite backup 复制约 217 MiB 的真实业务数据库及画像、图片缓存到仓库外的私有临时目录；API / 图片服务使用 18422 / 18423，不覆盖原有 18420 / 18421 服务。
- 实际监听 `0.0.0.0:18422`。真实 `/api/qr-info` 返回 LAN、系统 Tailscale IPv4 / IPv6 与有效端口；没有把 loopback 写入手机二维码。
- 在实际桌面 Web「手机版」面板切换 LAN / 系统 Tailscale；另用「公网 / 自定义」输入已有 Tailscale 对端地址，取得三个实际 SVG 矩阵。共享编码器生成的矩阵与真实 DOM 指纹逐项一致，再栅格化为设备输入；不伪造接口响应或业务数据。
- 「自定义」中的 Tailscale 地址仍是私网测试，不计为公网通过。二维码、具体地址、原始日志及配置只保存在本机私有临时目录。

## 已完成的真实请求

## 原生 App 与手机网页

配套 App 分支从 `e5c8f89` 继续。Android API 35 ATD、`mobile_scanner` 随包原生 MLKit；只对显式指定的模拟器运行。真实 LAN PNG 原生解码成功；扫描页 UI / 相机流的独立验收未通过。

相机模式没有替换 `BackendScanView` 或扫描回调。Android 软件相机读入同一 Web 二维码画面；它不代表实体摄像头光学拍摄。首次输入的 1280×720 画面在实际预览里把二维码裁掉半边，三个定位角未完整出现，45 秒后得到 `lan: scan import did not complete`。另一次安装后相机权限被重置，启动停在权限弹窗；均不计为通过。已保留实际截图并缩小、移动模拟器输入的二维码；随后冷启动超过四分钟仍未 ready，`sys.boot_completed` 为空，未能执行调整后的相机或三地址 transport-only 运行，不能把参数构建成功写成通过。

验收脚本从不可达的旧地址开始，避免“原本已经是目标地址”造成误判；成功条件包括真实设置导入、推荐加载、偏好存储重新读取和新客户端 ping。相机验收不预先创建第二个图片分析控制器，PNG 分析与相机流分开运行。无 UI 的 transport-only 模式不能计入设置页 / 相机通过。

手机网页的真实 HTML / 资源 / API 请求成功；浏览器在手机页 DOM 采集时超时，目前未取得实际推荐卡片渲染通过证据。

配套 App 最终 `flutter analyze --no-pub` 无问题（9.7 秒），解析 / 设置 / 轻量连通性回归 **45 passed，37 秒**；这组是单元 / widget 回归，不能替代设备扫码。最终 Android x64 相机参数包及三地址 transport-only 参数包构建成功；设备未完成项目仍按上述结果保留。

## 仍缺少的验收条件

- **公网**：本机未配置 Serve / Funnel，也没有已知可用的公网后端 URL，未验证公网 HTTPS、代理前缀或跨公网扫码；没有为测试开放数据库的公网入口。
- **Vibe**：尚未确认这是指本项目 Web 面板，还是另一个项目的二维码。本轮只验证本项目 Web 产生的码，不能宣称兼容未提供的外部码。
- **相机完整连接**：原生 PNG 解码、API 可达分别有证据，但目前未取得“相机识别 → 自动保存 → 真实推荐 → 恢复后重连”的整条成功记录。
- **实体 / 跨物理网络**：按用户要求不使用实体手机，同机模拟器与两个节点的结果不外推到蜂窝网络。

配套 App 的最终设备结果维护于 `docs/backend-connection-qr.md`。本次没有发布或替换正式安装包。
