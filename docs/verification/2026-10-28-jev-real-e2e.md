# Jev 配置、上下文适配与真实请求复验（2026-10-28）

## 结论与范围

在 `perf/jev-context-utilization` 独立 worktree，基于 `12085502` 的正式服务工厂、
lifespan、配置热更新、候选 coordinator、原生 Jev adapter 和 SQLite admission，
完成五组隔离验收及进程重启。无假的业务组件或模型答案；旁路 HTTP hooks 只检查输入和
记录长度、题数、响应 usage，不改变请求内容、认证或响应。

实际发送 **8 次 OpenRouter 原生请求，90 个 question，全部 HTTP 200 且完成有效评估**。
真实模型固定为 `typesafe/jev-1.14-20261014`，返回 provider `TypeSafe`；通过正式
`PUT /api/config` 将 Base URL `https://openrouter.ai/api` 规范化为
`https://openrouter.ai/api/v1/systemone`，显式选择 `eval_scorer=jev`，候选搜索上限 64，
两项额外 byte guard 均为 0（按已登记容量自适应）。

本轮不是部署：未修改或重启日常服务、日常配置及数据库；既有真实画像和视频快照仅只读复制。
B 站使用专用回环代理阻断范围外抓取，因此不包含当天源站抓取或安装版 MV3 人工验收。

## 正式配置事务与故障恢复

每组均等待 `apply-status.state=applied` 且 `applied_revision` 不小于保存返回的 revision，
再由公共候选入队接口和 `POST /api/recommendations/refresh` 唤醒正常后台链路。
核对实际配置读回、真实 HTTP、每条候选终态以及 runtime-status 的预算停放数。

| 场景 | 总 / state＋单题容量设置 | applied revision | 实际请求 / question | 候选终态 | 预算停放数 |
|---|---|---|---|---|---|
| 默认窗口 | 64,000 / 32,000 | 1 | 2 / 30 | 3 rejected_low_score | 0 |
| 缩小窗口 | 48,000 / 24,000 | 2 | 3 / 30 | 1 cached、2 rejected_low_score | 0 |
| 无法容纳必需输入 | 12,000 / 12,000 | 3 | 0 / 0 | 3 failed_eval，均 input_budget_exhausted | 3 |
| 原样再保存并唤醒 | 12,000 / 12,000 | 4 | 0 / 0 | 原三条继续停放 | 3 |
| 调大后恢复原三条 | 56,000 / 28,000 | 5 | 3 / 30 | 1 cached、2 rejected_low_score | 0 |

超限与原样再保存阶段所有候选 `eval_attempts=batch_eval_attempts=0`，短暂静默观察内无远端请求；
runtime 同时给出停放数与实际预算原因。恢复组没有手动重建原三条队列，由有效容量变化触发
正常有界恢复。不换模型、不转生成式 LLM、不伪造分数、不为压缩增加远端摘要调用。
阈值保持 0.60，低分拒绝属于完成评估，不是 HTTP 或解析失败；不同窗口分数不同，
不能据此认证推荐质量改善。

随后停止并重启自有隔离进程：Jev 开关、固定模型、规范化 endpoint、56,000/28,000 容量和
64 条搜索上限均保留；已完成候选未因重启再次请求。最终隔离服务已停止。

## 输入适配的实测证据

样本为 58,850 bytes 的真实源画像文件副本、114 个兴趣（有效目录 24,686 bytes）、
两条真实视频快照，以及一条明确标注为合成的长文压力样本（454 个源片段）。
每条候选有不可拆分的 10 个 question；第一个请求实际合批两条候选 / 20 题，
不是把三条候选分别反复评估后才合并结果。

| 请求 | 配置总 / 单题上限 | 实际总 / 最长单题 bytes | 所选兴趣数 | 实际 input / output tokens |
|---|---|---|---|---|
| 1：两条真实视频 | 64,000 / 32,000 | 49,418 / 31,376 | 18、16 | 19,152 / 1,496 |
| 2：合成长文 | 64,000 / 32,000 | 40,647 / 31,899 | 1 | 17,889 / 1,635 |
| 3：视频一 | 48,000 / 24,000 | 27,003 / 18,634 | 11 | 10,652 / 760 |
| 4：视频二 | 48,000 / 24,000 | 26,928 / 18,721 | 11 | 10,499 / 739 |
| 5：合成长文 | 48,000 / 24,000 | 32,642 / 23,894 | 2 | 13,823 / 1,264 |
| 6：恢复视频一 | 56,000 / 28,000 | 28,352 / 19,983 | 14 | 11,223 / 760 |
| 7：恢复视频二 | 56,000 / 28,000 | 28,258 / 20,051 | 13 | 11,084 / 739 |
| 8：恢复合成长文 | 56,000 / 28,000 | 36,642 / 27,894 | 2 | 15,864 / 1,444 |

- 共享必需画像 7,375 bytes 在所有有效请求中完整保留；选中的正向兴趣非空，全部可回溯
  到源目录，源目录本身不进入请求。不修改源画像，也不借用同行未选中的兴趣。
- 两条真实视频在三种有效窗口中分别完整保留 8/8、5/5 个原文片段。
  合成长文随窗口保留 105/454、64/454、84/454；条件句“必须先备份；否则不适用”保留，
  每个已发送片段均按源字段和字符 offset 验证原文一致。
- 默认窗口最长单题达到 31,899/32,000 bytes（99.7% 字节护栏利用率），但**不是 32K token
  满载证明**。容量整数目前以 1:1 映射到 UTF-8 byte ceiling，不是 Jev 精确 tokenizer。
  总请求和 state＋任一题双约束共同限制批次，不能为填满总窗口而突破单题窗口。
- 缩小/调大容量测试始终使用同一个真实模型，只证明用户配置的预算能驱动适配，
  不代表已实测其它模型的真实 tokenizer、官方极限或任意内容的语义无损压缩。

8 次远端耗时 1.179–3.068 秒，`usage.cost` 合计 **$0.004627812**。
真实请求阶段设单进程 8 次硬上限、每次最多一次传输尝试、首个非 200 后停止后续请求；
本轮无远端失败或重试，重启后的独立进程另外核对为零请求。

## 浏览器回归发现与修正

同轮执行已有真实 Chromium → Web 设置表单 → 正式配置保存 / 热更新 → 内容入队 →
原生 HTTP → 落库 / 页面重载测试，模型答案由本机合成 Jev 后端提供，**不是额外真实推理**。

首跑为 **2 failed、43 passed**（106.20 秒）。两个失败均为同一浏览器用例的 Base URL /
完整 endpoint 参数：测试后端限定 state＋单题 12,000 bytes，表单却填 16,000 token。
旧版自动预留 25% 时二者偶然一致，新版取消预留后不再一致。

最小公开 evaluator → loopback HTTP 探针保持画像、长文、模型和后端 12KB 限制不变，
仅改变配置容量：

- 配置 16,000：长文最长单题 15,862 bytes，后端按其声明的 12KB 容量返回 422；2/3 有效。
- 配置 12,000：同一长文变为 11,843 bytes，全部请求 200；3/3 有效。

据此仅将浏览器测试表单输入对齐为 12,000，并新增正式配置读回 `max_state_question_bytes`
必须为 12,000 的断言。保留合成后端的严格 12KB 限制、原文/条件句、三条缓存和 Token
不读回断言，没有修改生产压缩、模型解析、准入阈值或失败重试逻辑。

复跑命令：

```bash
PYTHONPATH=src pytest -q tests/test_jev_runtime_e2e.py tests/test_jev_context_budget.py tests/test_jev_on_demand_profile.py --tb=short --disable-warnings
```

复跑 **45 passed**（26.13 秒），包括真实 Chromium 的 Base URL / 完整 endpoint 两种表单
路径，以及正式进程重启持久化、双预算与画像按需加载回归。Ruff format / lint 和
`git diff --check` 均通过。不是全仓 pytest；插件安装版和手机真实设备不在本轮浏览器范围。
实际 OpenRouter Token 仅从临时环境变量读取；浏览器保存 Token 测试使用合成 Token，
不能把两种证据合写成“已在页面保存真实密钥并实测”。页面仍无独立的联网测试按钮。
