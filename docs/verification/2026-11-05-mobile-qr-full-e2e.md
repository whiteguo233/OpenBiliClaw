# 手机扫码连接真实环境复测（2026-11-05）

本轮只使用模拟器、实际构建的浏览器插件和正常 CLI 服务，没有操作实体手机。后端以 `b5a06559` 为基线补修手机网页代理前缀；App 以 `ea8b06f` 为基线，生命周期修复为 `f17a704`。源码分支和调试包的验收不等于商店或安装包已发布。

## 环境与数据

- 从实际在用数据库做约 216.8 MiB 的 SQLite 在线备份，在私有目录运行正常 CLI，API `18422`、图片服务 `18423`。停用本轮不需要的后台生产调度，API 进程设置 `OPENBILICLAW_WORKER=0` / `OPENBILICLAW_FULL_WORKER=1` 委托模式，未注入 API、HTTP、存储或推荐数据。
- 系统 Tailscale 使用已有账号和节点；既有应用内节点仍由原服务提供 `18420`。两个节点同机，模拟器经宿主 NAT / 系统 VPN 到达。没有将此结果算作手机系统 VPN 首次入网或跨蜂窝网络。
- 临时真实 HTTP / WebSocket 反代只发布长路径前缀，路径之外返回 404，转发原 API 的响应和 WS 字节。129 字节的二维码进入 v10。这个地址仍属局域网，不是公网验收。
- Chrome for Testing 加载实际构建的插件，未替换 Chrome API。先通过本机 TCP 转发连接默认端口，再在真实设置界面将插件端口改为 `18422` 并保存；二维码使用真实 `/api/qr-info` 的监听信息。截图直接取实际 Web / 插件二维码 DOM，没有向 App 传递解码字符串。
- Android 使用独立 API 31 AOSP ATD（720×1280）和官方 Fossify Gallery 1.14.1 处理系统选图。图片来自真实二维码面板截图，分别导入独立相册；图库只是测试环境工具，不是产品依赖。临时 AVD 启用原生 UI 绘制，避免 ATD 默认关闭绘制造成图库黑屏。

三个真实图库负例均通过：取消、空白图片、回环 QR 都不改变旧客户端或磁盘连接设置。实际相机权限拒绝由 Android PackageManager 确认，拒绝后仍通过生产扫码页选图；同一扫码页返回时没有因生命周期恢复重新弹窗。

同一进程随后用实际 Android WebView（Chromium 91）加载全部八个 URL，每项 **20 张实际推荐卡片**，就绪时 **2–18 张封面**成功解码；主机、端口和推荐路由均符合 QR。两组测试一次完成 **7 分 28 秒**，driver 退出码 **0**。

`OBC_LIVE_QR_GALLERY_FAILURES` 的原生选图等待观察实际离开 / 返回前台，再检查新帧，避免 Flutter 暂停出帧期间把旧按钮误当作选图完成。宿主取消图库时通过实际 resumed Activity 确认返回，避免耗时的 UI 树采集错过中间 App 帧、把下一次选图也取消。两项都属于验收工具同步问题，未通过注入扫码结果绕过。`OBC_LIVE_QR_DENY_CAMERA` 使用宿主确认实际 Android 权限状态后的阶段信号，未替换权限 API 或扫描结果。

完整进程重启用同一个二进制的两个实际进程：图库阶段完成后保留测试连接，宿主结束 App 进程并写入仅用于选择验证阶段的缓存标记，再启动；第二阶段执行生产 `app.main()`，不写后端设置，检查实际加载的协议、主机、端口、路径、连接方式，以及真实卡片和 ping。`OBC_LIVE_QR_KEEP_SETTINGS=true` 只可用于一次性模拟器。

最终单独用插件长路径 v10 做完整往返：第一进程实际图库识别、保存、20 条推荐、WebView 20 卡 / 16 张封面通过（52 秒）；结束进程后第二进程恢复同一连接，公开 API URL 保留完整前缀、加载 20 条真实推荐、首张卡片滚动到可见位置、ping 和设置入口通过（10 秒）。两个 driver 退出码均为 **0**。首次冷启动校验的内部路径格式比较和未等待 SliverList 绘制问题属于测试断言错误，已改用公开请求路径并等待真实卡片；未改动连接存储或注入卡片状态。

### Android 软件相机

另用生产相机入口（`OBC_LIVE_QR_CAMERA=true`），将实际 Web LAN 二维码的 188×189 截图像素原样放入 640×480 白色测试画面，通过 SDK `-camera-back imagefile:<frame.png>` 输入。首次居中放置时实际预览裁掉右侧，未识别；按已观察到的预览裁剪将截图移至 `(80,145)`，未重编码或缩放 QR。再次实际预览的三个定位角与静区完整可见。

最终相机帧 → 原生识别 → 生产扫描回调 → 保存目标 → **20 条真实推荐 / ping / 重读偏好重连**通过，约 **18 秒**，driver 退出码 **0**。没有选图、预先解码字符串或回调注入；此项属于模拟器相机帧验收，不代表实体摄像头光学拍摄。修正的是测试相机输入布局，没有改动产品相机布局。

iPhone 17 Pro / iOS 26.5 独立模拟器安装本轮原生 x86_64 debug 构建。浅色 / 深色分别通过 `app.main()` 打开生产主页、连接设置、URL 内扫码与粘贴图标、取消粘贴、扫码页右下角「选择图片」、返回设置；每轮 driver 退出码 0，分别约 26 / 21 秒。已保存实际设置页和扫码页截图，编译产物包含图片用途说明。模拟器用后已关闭并删除，未操作实体设备。

## 本轮发现与修复

1. 手机网页的资源、API、语言目录、封面和 WS 使用主机根路径，丢掉 QR 中的反代前缀。实际严格反代页面在 12 秒后仍没有推荐；API、WS、封面的三个回归分别先失败，再修正为相对手机入口解析。共享脚本和语言目录同步修正。原来的 JS 测试位置替身补成真实 URL 对象，资源顺序断言同步新相对路径，未删除原行为断言。
2. 扫码页按 `hasCameraPermission` 恢复相机，会把启动失败后的前台恢复也当成重试。回归先观察到 2 次启动，修正后只恢复切后台前实际运行的相机；连续后台状态及图片在后台完成也覆盖。新设备运行已确认一次相机请求后拒绝，图库取消返回并保持旧设置。
