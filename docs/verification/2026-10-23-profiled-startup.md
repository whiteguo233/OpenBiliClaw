# 性能采样后的启动与冷封面优化（2026-10-23）

## 结果

相对上一轮 `57a07adc`，这次去掉了实际测到的 CPU 重复工作，而非只调整请求顺序。完整网页冷封面交替对照中，首四张图片完成中位数从 4848ms 降到 3586ms（约 26%），滚动后八张全部完成从 6298ms 降到 4557ms（约 28%）。已预热图片缓存的热导航中，首四张从 2796ms 降到 2338ms（约 16%）。这些是本机隔离环境结果，不是用户 Windows Edge 部署的性能保证。

## 诊断与实现

1. **默认简体的翻译空转。** CPU 采样中 `activate` 约 114ms，其中 DOM `apply` 约 78ms。内置简体目录的 2916 条消息、210 个模式均为恒等映射。运行时现在直接使用源文案，首次简体启动不下载目录、不编译模式、不遍历隐藏设置的 DOM。切换到英／繁后仍记录源文案，切回简体恢复；观察器保留以恢复切换期间脱离 DOM、随后重新插入的节点。自定义目录不走该捷径。并发目录请求合并、旧语言响应不得覆盖新选择、失败目录可重试。
2. **启动强制布局。** `initBackToTop` 中同步 `getComputedStyle` 的采样约 139ms，发生在随后还会修改 DOM 的 `renderAll` 之前。现在将启动、滚动和 resize 的读取合并到下一帧；回到顶部功能保持。没有删掉列表滚动加载的边距检查。
3. **每张冷图重复解析默认 CA。** 原 `ImageTransport` 为每个已验证的请求跳创建 SSLContext。20 样本微基准中每次约 88ms。现在最多缓存四份默认 CA 上下文，按信任模式、PID 和证书包路径／stat 标识区分，证书包变化即重建。环境自定义 CA 不缓存，保持每次重载。仍逐跳验证公网 DNS、固定连接 IP、使用原主机名 Host/SNI、验证证书并关闭独立连接。DoH 和 HTTPS 代理使用同一 helper，不缓存路由。`certifi` 本已由 HTTPX 安装且打包清单已包含，本次显式声明直接使用；无新服务、配置或安装步骤。

[CPU 采样摘要](assets/2026-10-23-profiled-startup/cpu-summary.json)仅用于定位，不以单次 profiling 的总耗时计算性能提升。两个性能回归在修改前均失败：默认简体仍请求目录／遍历 DOM；启动顶部控件仍同步读取布局。网络回归旧实现创建两次 SSLContext，修复后一次，同时仍解析两次 DNS、建立并关闭两条连接。

## 真实网页：已预热图片

真实后端、SQLite、八条本机真实内容和真实封面，浏览器 Chromium 1440×1000。为隔离推荐算法，本次使用独立数据库的验收推荐记录，不调用模型或发评论。数据文件与模型配置仅保留在权限受限的临时目录，结束清理。基线与修复静态文件在同一个 API 进程交替提供，ABBA BAAB 共八组、十六次导航，每组先禁用浏览器缓存，再允许缓存。无请求拦截，无假图片。性能测试期间未并行运行本任务测试；用户机器其他进程仍有较高 CPU 负载，未干预。

| 中位数 ms | 基线 | 修复 | 变化 |
| --- | ---: | ---: | --- |
| 禁用浏览器缓存：卡片出现 | 2351.5 | 2286.4 | 快约 3% |
| 禁用浏览器缓存：首四张图片完成 | 2629.5 | 2457.5 | 快约 7% |
| 允许浏览器缓存：卡片出现 | 2591.1 | 2024.8 | 快约 22% |
| 允许浏览器缓存：首四张图片完成 | 2795.8 | 2338.2 | 快约 16% |

| 允许浏览器缓存：长任务总时长 | 586.0 | 420.5 | 少约 28% |

默认简体目录请求在旧版每次一次，修复版每次零次。每组仅四个样本，有旧版快于新版的轮次，不能将百分比视为统计显著或跨机器保证。因为负载与请求时间波动，热导航绝对值不一定小于冷导航；也不能与上一轮较空闲时的绝对耗时直接比较。[原始十六次导航](assets/2026-10-23-profiled-startup/ab.json)。

## 真实 CDN：绕过图片缓存

以生产 `fetch_cover_bytes` 直接并发获取相同八张 CDN 图片，按 before / after / after / before 执行；每轮修复版清空默认 TLS 上下文缓存，包含首次 CA 解析成本。旧 transport 从基线源文件加载，其他调用使用相同环境；不模拟网络、不读取图片磁盘缓存。四轮 32 次全部成功，每张图的 SHA-256 在四轮一致。

| 八图批次 | 基线 | 修复 | 修复 | 基线 |
| --- | ---: | ---: | ---: | ---: |
| 完成时间 ms | 906 | 376 | 355 | 819 |
| 创建 SSLContext 次数 | 8 | 1 | 1 | 8 |
| SSLContext 总耗时 ms | 528 | 67 | 66 | 525 |

批次中位数约 862→365ms（约快 58%）；这是封面下载链路，不等于整页提升。这里通过减少七次证书解析解释了主要收益，避免把单纯 CDN 波动当作结论。[批次详情](assets/2026-10-23-profiled-startup/cold-cdn.json)、[独立 CA 微基准](assets/2026-10-23-profiled-startup/ssl-context-before.json)。

## 验证与边界

- Node 共享 i18n 行为测试 9 项通过，涵盖语言往返、动态文本与属性、受保护内容、目录并发／失败重试／源更换。
- 真实浏览器和真实目录请求验证 `Save Configuration → 儲存配置 → 保存配置` 的文本与 title 同步恢复。
- 桌面列表稳定性、滚动预载边距、顶部控件、后台会话、i18n 等六份回归共 59 项通过；其中新增顶部控件回归先红后绿。
- 使用 `PYTHONPATH=src` 的本分支 Python i18n、图片缓存、DNS/TLS 网络边界及 CA 缓存回归共 127 项通过。使用共享虚拟环境时显式指定源码路径，避免导入主工作区的 editable 安装。
- Ruff lint/格式、JavaScript 语法检查与 `mypy src/` 通过（361 个源文件）。
- 代码独立只读复核没有发现需修正的问题；该复核未重复性能测量。

没有修改对外接口、配置、进程分工或安装路径。未合入 main、部署到用户电脑或发布安装包；实际用户环境仍需升级到包含这些改动的版本才能受益。外部 CDN 网络耗时仍然存在，本次没有承诺所有环境都能秒开。
