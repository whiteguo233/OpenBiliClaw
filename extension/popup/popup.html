    默认调用链

    按顺序请求；失败、超时或限流时自动尝试下一项。

      模块路由

      🤖 LLM 模型

      默认空；只有显式选择备选 Provider 时才会 fallback，不再自动尝试其它 Provider。

      备选与默认 Provider 相同时永远不会生效，保存会被拒绝；请换一个不同类型的 Provider 或留空关闭 fallback。

      适配 Groq / Together / Azure OpenAI / vLLM / 自建等任何走 OpenAI 协议的服务。Base URL 必填，否则等同于普通 OpenAI provider。

      Embedding 与 LLM 各自独立配置，Provider 留空时不会跟随默认 LLM。Claude / DeepSeek / OpenRouter 没有 embedding 接口，未在此列出。

      ⏰ 调度

      开启后会暂停定时发现、候选池预计算和画像更新中的 LLM / embedding 调用；推荐列表不再自动补充，候选池为空时可能暂时没有推荐，建议初始化完成并已有内容后再开启。

      默认关闭。开启后仍需要到「平台源」页为对应来源单独打开“允许扩展周期回拉”；这些任务可能打开前台标签页抓取账号数据。

      开启后，当所有扩展窗口断开时，后台 LLM / embedding 工作会在宽限期后自动暂停；重新打开浏览器后恢复，离线期间不会自动补新内容。

      此开关不会更新浏览器插件；插件商店安装由浏览器处理，zip / 开发者模式加载需要手动下载新版并重新加载。

      候选评分模式

      Agent 沿用完整 AI 评估与缓存，是默认生产模式；Shadow 同时计算 learned 分数但仍由 Agent 决定推荐，用于积累对照；Learned 仅应在人工运行质量门禁并确认通过后，让 learned 分数决定后续候选的相关性。Shadow 与 Learned 当前仍会调用 Agent 生成时效、主题和风格元数据，不是降本开关；切换不会重算已有推荐。

      推荐增强

      P1 用户视觉画像、P2 弹幕语义、P3 视频关键帧本质都是排序信号加权，不是过滤。P1/P3 依赖多模态 image embedding，P2 只需文本 embedding；P1 每个极性反馈不足 8 条时会安全 no-op。关闭开关会保留缓存与参数并回退到原排序，不影响现有主流程；关键帧和弹幕目前仅作用于 B 站。

      多模态处理

      “图像 Embedding 能力”与“候选封面参与 LLM 评估”相互独立：前者控制图像向量能力，供 P1/P3 使用；后者把候选封面送入 LLM 评估。P1/P3 依赖前者，不依赖后者。

      需多模态 embedding 模型（Gemini gemini-embedding-2 或 DashScope qwen3-vl-embedding）。开启后封面和关键帧可单独编码为向量；纯文本模型会自动跳过。默认关闭。

      开启后，支持图像输入的评估模型会把候选封面随文本一起判断；图片会先压缩，图文 batch 默认更小。它不控制 P1/P3 的图像 Embedding。

      范围 1–3，默认 3（每批最多 30 条、最多 90 条在途）；后端会为聊天等交互保留一个全局 LLM 槽位，实际并发可能更低。

      搜索词生成

      经典：仅用合并关键词生成器；混合：在经典基础上再叠加 search-backed 灵感轴链路（最丰富，但同时跑两套，混合最贵）；灵感：完全用灵感轴链路替代经典。

      认知循环预算

      觉察 / 洞察每轮 LLM 调用的输入批量与输出 token 上限。默认按 256K 上下文模型设计；80-100K 上下文的本地模型（如 qwen3.8-27B）可调小，无需改源码。
